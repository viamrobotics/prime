The component classes are `@utility` classes shipped by `@viamrobotics/tailwind-config`. They style native elements, bits-ui triggers in prime-ui (`<Dialog.Close class="icon-button">`), and markup outside Svelte.

Each example below is static HTML wearing the class list it shows. Hover is not rendered statically, so the tables name the hover change in words.

A bare class is the design-system default. A modifier beside it recolors, as in `class="button button-primary"`. Utilities written after the class win, so `class="button px-4"` overrides the padding.

## pill

Modifier: `pill-outline`. A removable pill holds a button child with an accessible name.

<div class="not-content flex flex-wrap items-center gap-3 rounded-sm border border-light p-4">
  <span class="pill">Lion</span>
  <span class="pill pill-outline">Tiger</span>
  <span class="pill">
    Lion
    <button type="button" aria-label="Remove Lion">
      ×
    </button>
  </span>
  <span class="pill" aria-disabled="true">
    Disabled
  </span>
  <span class="pill" aria-readonly="true">
    Read only
  </span>
</div>

On a plain `<span>`, `aria-disabled` and `aria-readonly` are CSS hooks only. Assistive technology reads no state from them, so a removable pill signals its state through the remove button's own `disabled` attribute.

<Code
  lang="html"
  code={`<span class="pill">Lion</span>
<span class="pill pill-outline">Tiger</span>
<span class="pill">
  Lion
  <button type="button" aria-label="Remove Lion">×</button>
</span>
<span class="pill" aria-disabled="true">Disabled</span>
<span class="pill" aria-readonly="true">Read only</span>`}
/>

| State     | Attribute                | What changes                                |
| --------- | ------------------------ | ------------------------------------------- |
| Disabled  | `[aria-disabled="true"]` | Disabled colors and a `not-allowed` cursor. |
| Read only | `[aria-readonly="true"]` | Disabled colors, with the default cursor.   |

## progress-dots

A braille spinner. It freezes on its first frame under `prefers-reduced-motion: reduce`.

<div class="not-content flex flex-wrap items-center gap-3 rounded-sm border border-light p-4">
  <span class="progress-dots" role="status">
    <span class="sr-only">Loading</span>
  </span>
</div>

<Code
  lang="html"
  code={`<span class="progress-dots" role="status"><span class="sr-only">Loading</span></span>`}
/>

`progress-dots` has no states.

<Aside type="caution" title="Give it a label">
  `progress-dots` carries `role="status"` and a visually hidden label as a
  child. Inside a busy button, hide it with `aria-hidden="true"` and let
  `aria-busy` carry the meaning.
</Aside>

Each state also applies when the attribute sits on a direct child `<input>` of the frame. On a native single `<select>`, the class replaces the browser's arrow with a chevron and pads the right edge for it, so the frame reads the same as a text field.

| State     | Attribute                        | What changes                                |
| --------- | -------------------------------- | ------------------------------------------- |
| Hover     | `:hover`                         | A darker border.                            |
| Invalid   | `[aria-invalid="true"]`          | A danger border.                            |
| Warning   | `[data-field-state="warn"]`      | A warning border.                           |
| Read only | `[readonly]`                     | A transparent border and a gray background. |
| Disabled  | `:disabled` or `[data-disabled]` | Disabled colors and a `not-allowed` cursor. |

Later states win ties. Disabled and read only beat invalid and warning, and every state beats hover.

<Aside title="Warning state">
  `input` reads `data-field-state="warn"`. prime-ui's `Field` sets it, and plain
  markup can set it directly.
</Aside>

## focus-ring and focus-ring-within

`focus-ring` draws a 2px outline offset by 2px on `:focus-visible`. `button`, `icon-button`, and `input` already include it. `focus-ring-within` draws the same ring on a frame whose focus lives on a child, and it silences the child's own ring.

| State          | Attribute                                    | What changes                      |
| -------------- | -------------------------------------------- | --------------------------------- |
| Keyboard focus | `:focus-visible` (`focus-ring`)              | The outline appears.              |
| Focus inside   | `:has(:focus-visible)` (`focus-ring-within`) | The outline appears on the frame. |

## z layers

The config names the stacking order of floating UI, so a popover opened inside a dialog clears the dialog and a tooltip clears both. Each layer is a `z-*` class backed by a `--z-*` token. Bare numbers such as `z-50` and `z-1150` still work, and steps of 100 leave room for a bare value between layers.

| Class       | Token         | Value | What sits on it                                                          |
| ----------- | ------------- | ----- | ------------------------------------------------------------------------ |
| `z-sticky`  | `--z-sticky`  | 100   | Headers and docked bars.                                                 |
| `z-overlay` | `--z-overlay` | 1000  | A dialog's backdrop.                                                     |
| `z-dialog`  | `--z-dialog`  | 1100  | The dialog panel.                                                        |
| `z-popover` | `--z-popover` | 1200  | Popovers, select panels, and comboboxes.                                 |
| `z-menu`    | `--z-menu`    | 1200  | Menus. Same value as `z-popover`, so a consumer never has to know which. |
| `z-toast`   | `--z-toast`   | 1300  | Notifications.                                                           |
| `z-tooltip` | `--z-tooltip` | 1400  | Above everything that can carry a hovered control.                       |
| `z-max`     | `--z-max`     | 9999  | Reserved. Nothing may cover it.                                          |

    Dialog panel
  </div>
</div>

<div role="tooltip" class="z-tooltip absolute">Tooltip text</div>`} />
