- A real `<input>`, so every native attribute and event handler passes straight through.
- `bind:value` plus `oninput`, `onchange`, `onblur`, and the rest, side by side.
- Four contextual states, `none`, `info`, `warn`, and `error`, with a matching `Input.StateIcon`.
- Reads `id`, `disabled`, `required`, `state`, and `aria-describedby` from an enclosing [`Field`](../field/).

## Anatomy

```svelte

  <Input.StateIcon />
```

## Usage

### Two-way binding

`bind:value` on the input. Inside a `Field` the label and hint wire themselves to it.

<Example code={twoWaySource} title="TwoWay.svelte">

### Validation on blur

The input is native, so `onblur` and the other handlers work alongside the binding. Set `state` on the field and the input frame, the hint, and the `StateIcon` all follow it.

<Example code={validatedSource} title="Validated.svelte">

## Styling

`class` lands on the bordered frame, which is the visible control. The frame carries the state border and the disabled and read-only backgrounds. `Input.StateIcon` takes `class` on its `<svg>`, merged with the state color. The input sets `aria-invalid` in the error state, so `aria-invalid:` variants work on the inner element.

## Keyboard

Native text input behavior. Nothing is added or intercepted.
