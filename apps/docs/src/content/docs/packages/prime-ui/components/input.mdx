- A real `<input>`, so every native attribute and event handler passes straight through.
- `bind:value` plus `oninput`, `onchange`, `onblur`, and the rest, side by side.
- Three contextual states, `info`, `warn`, and `error`, each with a matching [`Field.StateIcon`](../field/). `none` shows no icon.
- `Input.Group` frames the input with icons, units, and buttons.
- Reads `controlId`, `disabled`, `required`, `state`, and `aria-describedby` from an enclosing [`Field`](../field/).

## Anatomy

`Input` is one bare `<input>` and needs no parts. `Input.Group` is a part for adornments. Inside it the input goes borderless and the group wears the frame. Children go in any order.

```svelte
<Input />

<Input.Group>
  <Icon />
  <Input />
  <span>unit</span>
  <Field.StateIcon />
  <button>trailing action</button>
</Input.Group>
```

## Usage

### Two-way binding

`bind:value` on the input. Inside a `Field` the label and hint wire themselves to it.

</Example>

### Validation on blur

The input is native, so `onblur` and the other handlers work alongside the binding. Set `state` on the field and the input, the hint, and the `Field.StateIcon` all follow it.

<Example code={validatedSource} title="Validated.svelte">

For the controlled mode, where your setter can decline a keystroke, see [State & binding](../state/).

### With adornments

A leading `Icon`, the input, and a unit suffix inside an `Input.Group`. You set the width, here with `class="w-64"` on the group. Pressing the group's padding or the icon focuses the input.

<Example code={adornedSource} title="Adorned.svelte">

</Example>

### States

Put a `Field.StateIcon` after the input inside an `Input.Group` to show the icon within the border. Standalone it takes its own `state`, and inside a `Field` it follows the field.

## Styling

`class` lands on the `<input>`. The input has no wrapper and no layout utilities, including no width, so set one yourself or let a flex or grid parent stretch it.

`Input.Group` takes its border, its disabled and read-only backgrounds, and its state colors from the input inside it, through CSS `has-` variants. It takes `class` on its `<div>` and has no layout utilities either, so give it a width.

| Hook                | Where                                          |
| ------------------- | ---------------------------------------------- |
| `data-state`        | On the input for `info`, `warn`, and `error`   |
| `aria-invalid`      | On the input in the `error` state              |

`Field.StateIcon` takes `class` on its `<svg>`, merged with the state color.

## Keyboard

Native text input behavior. Nothing is added or intercepted.
