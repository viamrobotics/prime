## Props

<PropsTable name="field" />

`Field` renders a plain `<div>` and takes no layout stance, so pass `class` to stack or inline its parts. `id` is the control's id, not the wrapper's, so a known id still works for an external `<label for>` or a test selector.

## What the parts take from the field

| Part                        | Reads from `Field`                                                          |
| --------------------------- | --------------------------------------------------------------------------- |
| `Label`                     | `for` (the control id), `required`, `disabled`                              |
| `Hint`                      | `disabled`, `state` (error text turns red), and registers itself            |
| `Input`, `NumberInput`      | `id`, `disabled`, `required`, `state`, `aria-describedby`                   |
| `Checkbox`                  | `id`, `disabled`, `required`, `aria-describedby`                            |
| `RadioGroup`                | `id`, `disabled`, `required`, `aria-labelledby`, `aria-describedby`         |
| `Select` / `Select.Trigger` | `disabled`, `required` on the root; `id`, `aria-describedby` on the trigger |

A prop passed to a part directly always wins over the field's value.

## Without a field

Every part still works on its own. Wire it by hand with `for`, `id`, and `aria-describedby`:

```svelte
<Label for="email" required>Email</Label>
<Input id="email" aria-describedby="email-hint" required />
<Hint id="email-hint">We'll never share it.</Hint>
```
