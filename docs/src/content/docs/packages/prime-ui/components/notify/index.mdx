- Render one `Notify` region per app, below a `provideNotify`.
- `useNotify` has `info`, `success`, `warning`, `danger`, and `pending`. Each returns `{ id, dismiss }`.
- Each item is a [`Banner`](../banner/) with a countdown bar. `actions` puts a link or a button in its action row.
- `pending` has no timer and shows a spinner in the chip. `progress` draws a bar along the bottom while it runs.
- `persist: true` keeps a notification until the user dismisses it.
- `update` turns a pending notification into its result.

## Toast or notification?

A notification reports something that happened to the user, such as a failure, a lost connection, or long-running work. It carries a title and may persist. A [toast](../toast/) confirms an action the user just took, such as `Saved` or `Copied`, and goes away on its own.

## Anatomy

`Notify` is the region, and it renders one `Banner` per notification: title, description, an optional action row, the close button, and the countdown. Everything a notification shows comes from the `useNotify` call that made it, so the region takes no content.

```svelte
<script>
  provideNotify();
</script>

<Notify />
```

`pending` shows a spinner and never dismisses itself. `progress`, a percent from `0` to `100`, draws a bar along the bottom, and `update` moves it. Pass the id to `update` with a result variant to finish, which starts the countdown in the bar's place.

## Styling

`class` lands on the region. Each item is a `Banner`, so its look follows the [Banner](../banner/#styling) classes. The countdown bar fills in the variant's dark tone.

Each item carries data attributes for styling by state.

| Attribute        | Values                           |
| ---------------- | -------------------------------- |
| `data-state`     | `open`, `closed`                 |
| `data-paused`    | Present while the timer is held. |
| `data-first`     | Present on the newest item.      |
| `data-placement` | The provider's `placement`.      |

## API

<PropsTable name="notify" />

### useNotify

`useNotify` returns the methods below, and `provideNotify` returns the same object. The variant methods take `(title, description?, options?)`, where `description` is a string or a snippet and `options` takes `duration`, `persist`, `actions`, `progress`, and `onDismiss`.

| Method                | Description                                                              |
| --------------------- | ------------------------------------------------------------------------ |
| `info(...)`           | Shows an `info` notification and returns `{ id, dismiss }`.              |
| `success(...)`        | Shows a `success` notification.                                          |
| `warning(...)`        | Shows a `warning` notification.                                          |
| `danger(...)`         | Shows a `danger` notification.                                           |
| `pending(...)`        | Shows a spinner and no timer, with a `progress` bar when given one. Resolve it with `dismiss` or `update`. |
| `update(id, changes)` | Changes a visible notification in place. `changes` takes `variant`, `title`, `description`, `actions`, and `progress`. Fields left out keep their value. |
| `dismiss(id?)`        | Dismisses one notification, or every notification without an id.         |

`provideNotify` takes `placement` (default `top-end`), `duration` (default `8000` milliseconds), and `max` (default `5`).
