- Composed from parts, so the field, its trigger, and the calendar are yours to arrange.
- One `value`, bindable, with a `start` and an `end`. `open` is bindable too. `min` and `max` bound the selectable dates.
- `granularity` sets the smallest unit the field edits, from `day` down to `second`.
- `DateRangePicker.Field` takes `state` from an enclosing [`Field`](../field/), or directly. `error` and `warn` share the `input` [component class](../../tailwind-config/component-classes/) with [`Input`](../input/).
- The calendar floats in a portal, positioned to the field, and shades the days between the two ends.
- While the calendar is open, the field shows the darker `border-gray-9` frame, as `Select.Trigger` does.

## Anatomy

Every part is a property on `DateRangePicker`. `Field` is the segmented input, holding the start date, a dash, the end date, and the `Trigger` button that opens the calendar. `Content` is the floating panel, portaled to the body unless `portal` says otherwise, and holds the `Calendar`.

```svelte
<DateRangePicker>
  <DateRangePicker.Field>
    <DateRangePicker.Trigger />
  </DateRangePicker.Field>
  <DateRangePicker.Content>
    <DateRangePicker.Calendar />
  </DateRangePicker.Content>
</DateRangePicker>
```

## Usage

### Two-way binding

`bind:value` on the root. The value is a `DateRange`, an object with a `start` and an `end` that are each a `DateValue` from [`@internationalized/date`](https://react-spectrum.adobe.com/internationalized/date/). It is `undefined` until a date is chosen. With only one end chosen, the other is `undefined`, so a finished range is one with both ends set. Picking the end before the start in the calendar swaps them.

`name` submits the range as an ISO 8601 interval, `<start>/<end>`, and submits an empty value until both ends are set. A disabled picker submits nothing.

### Bounds

`min` and `max` take date objects from [`@internationalized/date`](https://react-spectrum.adobe.com/internationalized/date/), such as `new CalendarDate(2026, 1, 1)`. Dates outside the bounds cannot be selected in the calendar. A date typed outside them marks the field `aria-invalid` and paints the same error border as `state="error"`.

### Time of day

`granularity` of `hour`, `minute`, or `second` adds a time of day to each end, as on [`DatePicker`](../date-picker/).

### Presets

A preset such as "last 24 hours" belongs beside the control in the consuming app. It sets `value` to a range, and the picker shows it like any other.

### Accessible names

`DateRangePicker.Trigger` takes `aria-label`, which defaults to "Open calendar". `DateRangePicker.Calendar` takes `aria-label`, which defaults to "Choose a date range". It names the floating panel and starts the calendar grid's name, with the month and year appended. `DateRangePicker.Content` takes its own `aria-label` when the panel needs a different name. Set the trigger's and the calendar's to name them on a page that is not in English.

The previous and next month buttons take their names from the root `locale` through `Intl.RelativeTimeFormat`, such as "Last month" and "Next month" in `en-US`. They need no override.

### Placement

`DateRangePicker.Content` takes `side` and `align` to place the calendar, and `sideOffset` and `alignOffset` to nudge it. It opens below the field and aligns to its end by default. The API table lists each option and its default.

### States

`disabled` disables the field and its trigger. `readonly` shows the read-only frame and disables the trigger, so the calendar cannot open and the segments cannot be edited.

## Styling

`DateRangePicker.Field`, `DateRangePicker.Trigger`, and `DateRangePicker.Calendar` take `class` on the element they render. `DateRangePicker` takes no `class`, since it renders no element of its own. `DateRangePicker.Trigger` takes button attributes, and its `children` replace the calendar icon. The `previousChevron` and `nextChevron` snippets on `DateRangePicker.Calendar` replace the chevrons in its month buttons. `DateRangePicker.Content` wears `z-popover`. See [z layers](../../tailwind-config/component-classes/#z-layers).

Each day in the calendar carries these data attributes, set by bits-ui:

| Attribute                  | Set when                                                           |
| -------------------------- | ------------------------------------------------------------------ |
| `data-selection-start`     | The day is the start of the range.                                 |
| `data-selection-end`       | The day is the end of the range.                                   |
| `data-range-start`         | The day is the start of the range.                                 |
| `data-range-end`           | The day is the end of the range, or the start while no end is set. |
| `data-range-middle`        | The day is selected and is neither end.                            |
| `data-selected`            | The day is in the chosen range, ends included.                     |
| `data-highlighted`         | The day is in the preview between the start and the hovered or focused day. |
| `data-focused`             | The day holds the calendar's focus position.                       |
| `data-today`               | The day is today.                                                  |
| `data-outside-month`       | The day belongs to a neighboring month.                            |
| `data-outside-visible-months` | The day is outside every month on show.                         |
| `data-disabled`            | The day is disabled or outside `min` and `max`.                    |
| `data-unavailable`         | The day is unavailable.                                            |

The field frame sets `data-state` to `open` or `closed`, `data-disabled`, `data-readonly`, `data-invalid` for a typed date outside `min` and `max`, and `data-field-state` for `error` and `warn`. Each segment sets `data-segment` to its part, along with `data-invalid`, `data-disabled`, and `data-readonly`.
