- Composed from parts, so the input, the trigger, and the list are yours to arrange.
- One `value`, bindable, and a bindable `query` for the text typed since the list opened.
- `items` is the single source of truth for the options. The input shows the selected label, and `Combobox.Items` renders the ones the `filter` keeps.
- `Combobox.Input` takes `state` from an enclosing [`Field`](../field/), or directly. Both it and `Combobox.Trigger` sit in an [`Input.Group`](../input/).
- The list floats in a portal, lined up with the `Input.Group` around the input.
- To pick from a fixed list without typing, use [`Select`](../select/).

## Anatomy

Every part is a property on `Combobox`. `Content` is the floating list, portaled to the body, and should contain a `Viewport`. `Items` renders every match as a `Combobox.Item` and renders no element of its own. `Empty` shows only while nothing matches. `Group` and `GroupHeading` are optional.

```svelte
<Combobox items={options}>
  <Input.Group>
    <Combobox.Input />
    <Combobox.Trigger />
  </Input.Group>
  <Combobox.Content>
    <Combobox.Viewport>
      <Combobox.Items />
      <Combobox.Empty />
    </Combobox.Viewport>
  </Combobox.Content>
</Combobox>
```

## Usage

### Two-way binding

`bind:value` on the root holds the selection, and `bind:query` holds what the user has typed. `query` is empty while the list is closed. Put the combobox in a `Field` with a `Label` so the label targets the input.

<Example code={twoWaySource} title="TwoWay.svelte">
  <TwoWay client:visible />
</Example>

### Fully controlled

Pass `bind:value` a getter and a setter. [State & binding](../state/) explains both modes.

<Example code={controlledSource} title="Controlled.svelte">
  <Controlled client:visible />
</Example>

### Groups

Render `Combobox.Item` by hand to add structure. Wrap related items in `Combobox.Group` with a `Combobox.GroupHeading`. `items` stays on the root for the input's label, and reading `query` lets you drop groups with no match.

<Example code={groupedSource} title="Grouped.svelte">
  <Grouped client:visible />
</Example>

### Custom filter

The default `filter` keeps options whose label contains the typed text, ignoring case. Pass your own to change that. This one keeps labels that start with the text.

<Example code={customFilterSource} title="CustomFilter.svelte">
  <CustomFilter client:visible />
</Example>

### Remote options

For a long or remote list, fetch in the consumer. Read the bound `query`, load the matches, and pass them as `items`. Set `filter={() => true}` so the combobox shows them all instead of filtering again. The lookup here is simulated locally.

## Styling

Every part that renders an element takes `class` on that element. `Combobox` and `Combobox.Items` take no `class`. `Combobox.Items` renders no element of its own, and `Combobox` renders a visually hidden status region, plus a hidden form input when `name` is set. `Combobox` takes no event handlers either. `onfocus`, `onblur`, `onkeydown`, and the rest go on `Combobox.Input`, the real `<input>`. Focus shows as the same 2px ring every prime control uses. `error` sets `aria-invalid="true"` and the error border, and `warn` sets the warning border, both from the `input` [component class](../../tailwind-config/component-classes/). The panel width follows the input's frame, and its max height follows the space available. bits-ui sets the data attributes in the table below. `Combobox.Content` wears `z-popover`, described under [z layers](../../tailwind-config/component-classes/#z-layers).

| Part      | Attribute          | Value                                    |
| --------- | ------------------ | ---------------------------------------- |
| `Input`   | `data-state`       | `open` or `closed`                       |
| `Input`   | `data-disabled`    | present when disabled                    |
| `Input`   | `aria-invalid`     | `true` when `state` is `error`           |
| `Input`   | `data-field-state` | `info`, `warn`, or `error`, set by prime |
| `Trigger` | `data-state`       | `open` or `closed`                       |
| `Trigger` | `data-disabled`    | present when disabled                    |
| `Content` | `data-state`       | `open` or `closed`                       |
| `Content` | `data-side`        | the resolved side of the input's frame   |
| `Content` | `data-align`       | the resolved alignment                   |
| `Item`    | `data-selected`    | present when selected                    |
| `Item`    | `data-highlighted` | present under the pointer or keys        |
| `Item`    | `data-disabled`    | present when disabled                    |
| `Item`    | `data-value`       | the item's `value`                       |
