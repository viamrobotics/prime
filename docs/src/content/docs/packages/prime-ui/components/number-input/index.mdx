- Its own native `<input type="number">`. It takes the same `state` as [`Input`](../input/) and works inside an [`Input.Group`](../input/#anatomy) with a [`Field.StateIcon`](../field/).
- `value` is `number | undefined`. No string parsing on your side.
- `min`, `max`, and `step` are the native attributes. The browser owns stepping and the wheel.
- `NumberInput.Stepper` stands in for the browser's spin buttons and mirrors them.

## Anatomy

On its own, a `NumberInput` renders a frame that holds the native input and a `NumberInput.Stepper`. Inside an `Input.Group` it renders the bare input, and you place `NumberInput.Stepper` as the group's last child, after a suffix or a `Field.StateIcon`.

```svelte
<NumberInput />

<Input.Group>
  <NumberInput />
  <span>mm</span>
  <NumberInput.Stepper />
</Input.Group>
```

### Stepper

`NumberInput.Stepper` mirrors the browser's spin buttons. A press calls the input's `stepUp()` or `stepDown()`, so the value moves one `step` within `min` and `max`, and the input fires `input` and `change`. `bind:value`, a function binding that refuses the write, and your own `oninput` and `onchange` all see it. Holding a button repeats the step. The stepper is for a pointer only. It takes no focus, keeps focus where it is, and is hidden from assistive technology, since the input is already a spinbutton and the keyboard stays native. It shows while the frame is hovered or holds focus, and always on a touch screen. A disabled or read-only input hides it.

A standalone `NumberInput` renders one in place of the browser's spin buttons:

## Styling

`class` lands on the frame of a standalone `NumberInput`, and it carries no width. Every other attribute lands on the `<input>`. Inside an `Input.Group` the input goes borderless, `class` lands on the `<input>`, and the group carries the border. The stepper fills the frame's height and meets its right border at any frame size. The input carries `data-field-state` and `aria-invalid` from `state`.

## Keyboard

Native number input behavior: <kbd>ArrowUp</kbd> and <kbd>ArrowDown</kbd> step by `step` within `min` and `max`. Nothing is added or intercepted. `NumberInput.Stepper` takes no Tab stop, like the browser's spin buttons.
