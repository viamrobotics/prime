- Its own native `<input type="number">`. It takes the same `state` as [`Input`](../input/) and works inside an [`Input.Group`](../input/#anatomy) with a [`Field.StateIcon`](../field/).
- `value` is `number | undefined`. No string parsing on your side.
- `min`, `max`, and `step` are the native attributes. The browser owns stepping, spin buttons, and the wheel.

## Styling

Same as [`Input`](../input/#styling): `class` lands on the `<input>`, and it carries no width. Inside an `Input.Group` the input goes borderless and the group carries the border. The input carries `data-field-state` and `aria-invalid` from `state`.

## Keyboard

Native number input behavior: <kbd>ArrowUp</kbd> and <kbd>ArrowDown</kbd> step by `step` within `min` and `max`. Nothing is added or intercepted.
