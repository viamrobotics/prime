<SelectDemo client:visible />

- Composed from parts, so the trigger, the panel, and each item are yours to arrange.
- One `value`, bindable. `items` is the single source of truth for the options: it gives the closed trigger its label, drives typeahead while the list is closed, and `Select.Items` renders it.
- Keyboard navigation, typeahead, and the WAI-ARIA listbox pattern, via bits-ui.
- `Select.Trigger` takes `state` from an enclosing [`Field`](../field/), or directly. `error` sets `aria-invalid="true"` and a red border. `warn` sets a warning border. Both come from the same `input` [component class](../../tailwind-config/component-classes/) as [`Input`](../input/).
- The panel floats in a portal, positioned to the trigger, and scrolls when the list is long.
- One value at a time. For several, [`MultiSelect`](../multi-select/) takes the same parts with a `string[]` value.

## Anatomy

Every part is a property on `Select`. `Content` is the floating panel, portaled to the body. `Viewport` is the scrolling region, and `Content` should contain one. `Items` renders every entry of `items` as a `Select.Item`, and renders no element of its own. `Group` and `GroupHeading` are optional.

```svelte
<Select>
  <Select.Trigger>
    <Select.Value />
  </Select.Trigger>
  <Select.Content>
    <Select.ScrollUpButton />
    <Select.Viewport>
      <Select.Items />
    </Select.Viewport>
    <Select.ScrollDownButton />
  </Select.Content>
</Select>
```

To arrange items by hand, for example under group headings, compose `Select.Item` instead. `items` is still required on `Select` for the closed label.

```svelte
<Select items={options}>
  <Select.Trigger>
    <Select.Value />
  </Select.Trigger>
  <Select.Content>
    <Select.Viewport>
      <Select.Item />
      <Select.Group>
        <Select.GroupHeading />
        <Select.Item />
      </Select.Group>
    </Select.Viewport>
    <Select.ScrollDownButton />
  </Select.Content>
</Select>
```

### Rendering the options

Three ways turn `items` into rows. All three keep `items` on the root, which the closed trigger and typeahead read. The difference is who writes the loop.

| Approach                                  | Use it when                                                                                                                                               |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<Select.Items />`                        | Every option is its `label` plus a check when selected. The default, shown in the two-way example above.                                                 |
| `Select.Items` with a `children` snippet  | Every option shares one custom layout. The snippet receives `{ item, selected, highlighted }`, with `item` the entry from `items`.                       |
| `{#each}` over `Select.Item`              | The rows need something `items` cannot carry: extra data per row, groups, scroll buttons, or rows that are not one-to-one with `items`.                  |

### One snippet for every option

Pass `children` to `Select.Items`. The snippet sees `item` as a `SelectOption`, so `value`, `label`, and `disabled`. A row that needs more data per entry is the by-hand loop below. The trigger's chevron is an `indicator` snippet on `Select.Trigger` in the same way.

<Example code={customItemSource} title="CustomItem.svelte">
  <CustomItem client:visible />
</Example>

### Items by hand

Loop over your own data and render a `Select.Item` per entry. `Select.Item` takes the same `children` snippet without `item`, since the loop already has the entry in scope. `items` stays on the root so the closed trigger can show the selected label.

### Groups and scroll buttons

The by-hand form is also how you add structure. Wrap related items in `Select.Group` with a `Select.GroupHeading`. For a list taller than the panel, put `Select.ScrollUpButton` and `Select.ScrollDownButton` around the viewport. They appear only when there is more to scroll in that direction.

## Migrating from a native select

A prime-core `Select` was a native `<select>` with `<option>` children and an `onchange`. The same control here is `items` plus the six parts, and the value comes through `bind:value` instead of the event.

```svelte
<!-- before -->
<Select value={method} onchange={(event) => (method = event.currentTarget.value)}>
  {#each methods as method (method)}
    <option>{method}</option>
  {/each}
</Select>

<!-- after -->
<Select items={methods.map((value) => ({ value, label: value }))} bind:value={method}>
  <Select.Trigger class="w-full">
    <Select.Value placeholder="Pick a method" />
  </Select.Trigger>
  <Select.Content>
    <Select.Viewport>
      <Select.Items />
    </Select.Viewport>
  </Select.Content>
</Select>
```

`Select.Trigger` has no width of its own, so the `class` that sat on the old wrapper goes there. A `state` that sat on the old `<select>` goes on the trigger too, or on an enclosing `Field`.

## Styling

Every part that renders an element takes `class` on that element. `Select.Trigger` carries no width of its own, so set one with a class such as `w-64` or `w-full`. Focus shows as the same 2px ring every prime control uses. `Select` and `Select.Items` render no element, so they take no `class`, and `Select` takes no event handlers. `onfocus`, `onblur`, `onkeydown`, and the rest go on `Select.Trigger`, the real `<button>`. The panel width follows the trigger through `--bits-select-anchor-width`. Its max height follows `--bits-select-content-available-height`. bits-ui sets both variables. bits-ui also sets the data attributes in the table below. `Select.Content` wears `z-popover`; see [z layers](../../tailwind-config/component-classes/#z-layers).

| Part      | Attribute          | Value                             |
| --------- | ------------------ | --------------------------------- |
| `Trigger` | `data-state`       | `open` or `closed`                |
| `Trigger` | `data-disabled`    | present when disabled             |
| `Trigger` | `data-placeholder` | present while nothing is selected |
| `Trigger` | `aria-invalid`     | `true` when `state` is `error`    |
| `Trigger` | `data-field-state` | `info`, `warn`, or `error`, set by prime |
| `Value`   | `data-placeholder` | present while nothing is selected |
| `Content` | `data-state`       | `open` or `closed`                |
| `Content` | `data-side`        | the resolved side of the trigger  |
| `Content` | `data-align`       | the resolved alignment            |
| `Item`    | `data-selected`    | present when selected             |
| `Item`    | `data-highlighted` | present under the pointer or keys |
| `Item`    | `data-disabled`    | present when disabled             |
| `Item`    | `data-value`       | the item's `value`                |
