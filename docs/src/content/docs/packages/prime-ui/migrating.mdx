---
title: Migrating from prime-core
description: Where each piece of @viamrobotics/prime-core went in prime-ui.
---

`@viamrobotics/prime-core` shipped Svelte 4 components, actions, and helpers. `@viamrobotics/prime-ui` is Svelte 5 only, and some helpers did not carry over because the platform now covers them or because they were never UI. The table below maps each one to what you use now.

## What to use instead

| Old             | Now                                                                                               | Notes                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `uniqueId`      | `$props.id()`                                                                                     | Per instance and safe under SSR. No shim ships.                                          |
| `createHandleKey` | [`useHotkey`](../utilities/keybindings/)                                                           | Shortcuts register where the behavior lives and list from one registry.                  |
| `clickOutside` action | The [`clickOutside`](../utilities/click-outside/) attachment                                 | Use `{@attach clickOutside(handler)}`. Portaled content the element links counts as inside. |
| `persisted`     | Stays in your app                                                                                 | It is a storage helper and not UI.                                                       |
| `useToast`      | `provideToast` and `useToast`, see [Toast](../components/toast/)                                   | `provideToast` goes once near the root, and the `Toast` region renders the stack.         |
| `useNotify`     | `provideNotify` and `useNotify`, see [Notify](../components/notify/)                               | Same provider and consumer split as the toast.                                           |
| `Banner`        | [`Banner`](../components/banner/)                                                                  | Same name.                                                                               |
| `Progress`      | [`Progress`](../components/progress/)                                                              | Same name.                                                                               |

## Icons

`@viamrobotics/prime-core`'s `Icon` took a curated kebab-case name such as `icon="cog"`. `Icon` in prime-ui takes an import, so replace each name with the one below.

The tables cover a name written in markup. An icon that arrives as data, such as `name={option.icon}` or a field typed `IconName`, needs a map on your side from your own keys to the imports you use, since `Icon` in prime-ui carries none. Keep that map to the names your app renders.
