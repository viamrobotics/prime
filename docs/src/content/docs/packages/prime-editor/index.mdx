`@viamrobotics/prime-editor` is a CodeMirror 6 code editor for Svelte 5. It highlights with Viam's code tokens, so it follows the light and dark themes, and it can show a diff against another text.

<Aside type="caution">
  The public API is unstable until 1.0. Expect breaking changes in minor
  releases.
</Aside>

<Demo client:visible />

- `CodeEditor`, one editor with a bindable `value`.
- Six languages: TypeScript, JavaScript, JSON, Python, Go, and SQL.
- Optional line numbers, line wrapping, a placeholder, and readonly and disabled modes.
- Search and code folding from the keyboard.
- A unified or split diff view that opens when `original` is set.
- An invalid state through `aria-invalid`.

## Usage

Every editor needs a name. Pass `aria-label`, or `aria-labelledby` with the id of a visible label. In a split diff the original side reads as the name followed by "original", so the two textboxes are told apart: `aria-label` becomes `<name>, original`, and `aria-labelledby` adds a hidden `original` label after yours.

### Two-way binding

`bind:value` holds the document. Typing writes it, and assigning it from outside replaces the document. State that starts `undefined` shows an empty document.

<Example code={twoWaySource} title="TwoWay.svelte">

</Example>

### Function binding

A function binding receives each edit and decides what `value` becomes. This one refuses an edit past 60 characters by not assigning, and transforms every other edit to uppercase. The editor reads `value` back after each edit, so a refused edit is undone and a transformed one replaces what was typed.

</Example>

### Languages

`language` picks the grammar that highlights and indents the document. Omit it for plain text.

### Readonly

`readonly` blocks edits. The document stays focusable, selectable, and copyable.

<Example code={readonlySource} title="Readonly.svelte">

</Example>

### Disabled and placeholder

`disabled` turns the editor off, and it wins over `readonly`. Unlike `readonly`, it takes no focus and no selection, it leaves the tab order, and the textbox is marked `aria-disabled`. `placeholder` is the text shown while the document is empty.

<Example code={disabledSource} title="Disabled.svelte">
  <Disabled client:visible />
</Example>

### Gutter and wrapping

`lineNumbers` shows the gutter, which holds the line numbers and the fold markers. It is on by default. `wrapLines` wraps long lines instead of scrolling them horizontally. Both reconfigure the editor in place.

### Unified diff

Set `original` to open the diff view. `value` is compared against it, and the deleted and inserted lines share one editor.

<Example code={unifiedDiffSource} title="UnifiedDiff.svelte">
  <UnifiedDiff client:visible />
</Example>

### Split diff

Set `diff="split"` to put `original` beside `value`. The original side is readonly. `disabled` applies to both sides. Switching between unified and split rebuilds the editor, and so does changing `collapseUnchanged`. Every other prop change reconfigures it in place.

<Example code={splitDiffSource} title="SplitDiff.svelte">
  <SplitDiff client:visible />
</Example>

A long diff is mostly unchanged lines. `collapseUnchanged` folds each run of them into one row that expands on click, and keeps three lines of context around every change. Changing it rebuilds the editor.

### Validation

The editor does not validate the document. Check `value` yourself, then set `aria-invalid` to paint the error border and mark the textbox invalid. Point `aria-describedby` at the message so a screen reader reads it with the editor's name. Every `aria-*` attribute goes to the textbox, so `aria-errormessage` and `aria-required` work the same way. Every other attribute, such as `id`, `class`, or an event handler, goes to the editor's outer element.

<Example code={validationSource} title="Validation.svelte">

</Example>

### States

An editor is editable, readonly, disabled, or invalid. `aria-invalid` marks the invalid one, and the editor never sets it on its own.

## Styling

`class` lands on the outer element, and so does every other attribute that is not `aria-*`. Size the editor with a class there, and add `overflow-auto` for a document taller than its box. The `aria-*` attributes go to the editing surface.

Every color is a [tailwind-config](../tailwind-config/) token, so the editor follows the light and dark themes. `--color-gray-1` is the code surface in every state. A readonly editor drops its border, and a disabled editor keeps a transparent border on the disabled fill. The error border comes from `aria-invalid`.

A 2px `--color-link` outline at a 2px offset shows when the editing surface has keyboard focus. A click into a readonly editor shows no ring. An editable editor shows it on click too, as a native text input does.

The editor sets no data attributes.
