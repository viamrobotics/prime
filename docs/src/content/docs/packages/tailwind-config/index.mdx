`@viamrobotics/tailwind-config` is Viam's shared Tailwind CSS v4 configuration. It exposes design tokens as Tailwind v4 theme values in an `@theme {}` block plus an optional `./fonts` entry point that side-effect imports the variable-font packages.

<Aside title="Requires Tailwind v4">
  A Tailwind v4 bundler integration is required (`@tailwindcss/vite` or
  `@tailwindcss/postcss`). v3 is not supported.
</Aside>

       <Code
         code="yarn add --dev tailwindcss @viamrobotics/tailwind-config"
         lang="sh"

     </TabItem>

2. Import it from your app's main CSS:

   <Code code="@import '@viamrobotics/tailwind-config';" lang="css" />

3. (Optional) Load the variable fonts by adding a side-effect import in your app's entry point:

   <Code code="import '@viamrobotics/tailwind-config/fonts';" lang="ts" />

4. (Optional) Enable the dark theme by importing it _after_ the base config:

   <Code
     code={`@import '@viamrobotics/tailwind-config';\n@import '@viamrobotics/tailwind-config/dark';`}
     lang="css"
   />

</Steps>

## What it ships

- `tailwind-config.css` holds the `@theme {}` block of colors, spacing, fonts, shadows, and z-index tokens, plus the component classes.
- `tailwind-config-dark.css` (`./dark`) is the optional dark theme. It follows `prefers-color-scheme` by default, and a `.light` or `.dark` ancestor forces the mode. The class wins.
- `fonts.js` holds three `import '@fontsource-variable/*'` lines for Space Grotesk, Roboto Mono, and Public Sans.
- `theme-color.js` (`./theme-color`) exports `themeColor`, which reads a color token's value in script. See [Colors in script](#colors-in-script).

Token values match the [Viam design system](https://design.viam.com/). Don't invent values. Copy them from the published guides.

The package also ships the design system's [component classes](./component-classes/): `button`, `badge`, `input`, and more, as plain Tailwind classes.

## Dark theme scoping

The optional dark theme reassigns the `--color-*` tokens under a `.dark` ancestor, so utilities adapt with no markup changes. The four `--color-pixel-*` illustration colors keep their light values. A `.light` ancestor forces light mode, and the class wins over `prefers-color-scheme`. The button flips the `dark` class on the box itself, not on the page.

- `dark:` utilities follow the same rules as the tokens. They apply under a `.dark` ancestor and never inside a `.light` subtree.
- One level of `.light` inside `.dark` is supported. A `.dark` nested inside that `.light` flips the tokens but not `dark:` utilities.
- The dark palette is derived from the light tokens, and the grayscale ramp is inverted, so `bg-white` is not literally white in dark mode.

## Colors in script

A canvas, a WebGL scene, or a map marker needs a concrete color, where a class or `var()` cannot reach. `themeColor` reads a token's current value from the page.

<Code
  code={`import { themeColor } from "@viamrobotics/tailwind-config/theme-color";

const hovered = themeColor("--color-solar-power-bright");`}
  lang="js"
/>

- Write the whole custom property name as a literal at the call site. Tailwind emits a theme variable only when a scanned source file names it in full. A name built from parts, such as `` `--color-${tone}` ``, reads as unset.
- Your Tailwind build has to scan the file that makes the call. A package that calls `themeColor` needs an `@source` entry in the app, as it does for its classes.
- It returns the value as the stylesheet writes it, or `undefined` when the token is unset.
- Pass the element the color is drawn on as the second argument to follow a `.dark` or `.light` subtree. It defaults to the document root.
- It reads `document` when called, so call it in the browser. The import is safe on a server.
- `ThemeColorName` is the union of every color token.
