The component classes are `@utility` classes shipped by `@viamrobotics/tailwind-config`. They style native elements, bits-ui triggers in prime-ui (`<Dialog.Close class="icon-button">`), and markup outside Svelte.

Each example below is static HTML wearing the class list it shows. Hover is not rendered statically, so the tables name the hover change in words.

A bare class is the design-system default. A modifier beside it recolors or changes the fill, as in `class="button button-danger button-outline"`. Utilities written after the class win, so `class="button px-4"` overrides the padding.

## button

Two kinds of modifier compose. A color sets the family: `button-dark` is the neutral family at the solid fill, the design system's `dark` variant, and `button-danger`, `button-warning`, `button-success`, `button-info`, and `button-pending` are the semantic solids. A fill changes how the family paints: `button-outline` keeps the light background with the family's border and text, and `button-ghost` drops the background until hover. `button` alone is the default: the neutral family at the outline fill. Solid text picks black or white through `contrast-color()` where the browser supports it, white elsewhere.

Every color modifier in every fill and state. The markup below is the grid, cell for cell.

<ButtonMatrix />

| State    | Attribute                               | What changes                                               |
| -------- | --------------------------------------- | ---------------------------------------------------------- |
| Disabled | `:disabled` or `[aria-disabled="true"]` | Disabled colors and a `not-allowed` cursor, with no hover. |
| Busy     | `[aria-busy="true"]`                    | The cursor becomes `progress`.                             |

`button-group` on a wrapper joins its direct children into one segmented control. The children are usually `button`s, and any bordered child joins the same way. Neighbors share a single border and only the outer corners round. An enabled button stacks above a disabled one so the borders beside a disabled button stay visible. A hovered or focused button draws above its neighbors, so its border and focus ring are never covered. It works with every color, fill, and size modifier. Neighbors of the same solid fill show no divider, because the border is the fill color. Give the wrapper `role="group"` and an `aria-label`.

## icon-button

It takes the same `button-*` color and fill modifiers. `icon-button` alone is the neutral ghost, `icon-button button-outline` is the bordered treatment, and `icon-button button-danger button-ghost` tints the glyph.

<ButtonMatrix kind="icon-button" />

| State    | Attribute                               | What changes                               |
| -------- | --------------------------------------- | ------------------------------------------ |
| Disabled | `:disabled` or `[aria-disabled="true"]` | Gray icon, `not-allowed` cursor, no hover. |
| Busy     | `[aria-busy="true"]`                    | The cursor becomes `progress`.             |

<Aside type="caution" title="Name the button">
  An `icon-button` has no visible text, so it must carry `aria-label` or
  `aria-labelledby`.
</Aside>

## underline-tabs

A strip of tabs that marks the selected tab with a line under its label. `underline-tabs` is the strip, a row of tabs 16px apart over a 1px bottom border. `underline-tab` is one tab in it. The selected tab draws a 2px `gray-9` line over the strip's border and sets its text semibold. Hover gives an enabled tab the default text color. Keyboard focus draws the shared outset ring, because this strip does not scroll.

## file-tabs

A strip of compact, boxed tabs, like an editor's file tabs. `file-tabs` is the strip, one 35px row that scrolls sideways and never wraps, and `file-tab` is one tab in it. The selected tab carries a line on top and drops its bottom border, so it joins the content below. Hover darkens an enabled, unselected tab, and keyboard focus draws the `focus-ring-inset` ring, because the strip's scroll container clips anything drawn outside a tab. `file-tab-slot` is a placeholder cell in the strip, such as the spot where a dragged tab will land. It fills the row's height and draws the same separator as a `file-tab`'s right edge.

## banner

Modifiers: `banner-info`, `banner-success`, `banner-warning`, `banner-danger`, `banner-pending`, and `banner-block`. A banner reads no attributes, so give it a `role` of `status` or `alert`. A `banner-title` inside switches it from the compact one-liner to the stacked layout.

Every tone in the compact and the stacked layout, then `banner-block`, `banner-progress`, and `banner-details`. A warning banner fills its `banner-progress` with `--color-warning-text`, as it does its chip glyph, so the fill holds 3:1 on the gray track.

## focus-ring, focus-ring-within, and focus-ring-inset

`focus-ring` draws a 2px outline offset by 2px on `:focus-visible`. `button`, `icon-button`, and `input` already include it. `focus-ring-within` draws the same ring on a frame whose focus lives on a child, and it silences the child's own ring. `focus-ring-inset` is the same ring at an offset of -2px, for a control flush against a clipping edge such as a scroll container. `file-tab` includes it.

| State          | Attribute                                    | What changes                      |
| -------------- | -------------------------------------------- | --------------------------------- |
| Keyboard focus | `:focus-visible` (`focus-ring`)              | The outline appears.              |
| Keyboard focus, inset | `:focus-visible` (`focus-ring-inset`) | The outline appears inside the edge. |
| Focus inside   | `:has(:focus-visible)` (`focus-ring-within`) | The outline appears on the frame. |

## toast-stack-item

`toast-stack-item` holds the stacking styles of a toast or notification item. ## z layers

The config names the stacking order of floating UI, so a popover opened inside a dialog clears the dialog and a tooltip clears both. Each layer is a `z-*` class backed by a `--z-*` token. Bare numbers such as `z-50` and `z-1150` still work, and steps of 100 leave room for a bare value between layers.

| Class       | Token         | Value | What sits on it                                                          |
| ----------- | ------------- | ----- | ------------------------------------------------------------------------ |
| `z-sticky`  | `--z-sticky`  | 100   | Headers and docked bars.                                                 |
| `z-overlay` | `--z-overlay` | 1000  | A dialog's backdrop.                                                     |
| `z-dialog`  | `--z-dialog`  | 1100  | The dialog panel.                                                        |
| `z-popover` | `--z-popover` | 1200  | Popovers, select panels, and comboboxes.                                 |
| `z-menu`    | `--z-menu`    | 1200  | Menus. Same value as `z-popover`, so a consumer never has to know which. |
| `z-toast`   | `--z-toast`   | 1300  | Notifications.                                                           |
| `z-tooltip` | `--z-tooltip` | 1400  | Above everything that can carry a hovered control.                       |
| `z-max`     | `--z-max`     | 9999  | Reserved. Nothing may cover it.                                          |

<div role="tooltip" class="z-tooltip absolute">Tooltip text</div>`} />
