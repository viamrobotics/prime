Component classes

The component classes are @utility classes shipped by @viamrobotics/tailwind-config. They style native elements, bits-ui triggers in prime-ui (<Dialog.Close class="icon-button">), and markup outside Svelte.

Each example below is static HTML wearing the class list it shows. Hover is not rendered statically, so the tables name the hover change in words.

A bare class is the design-system default. A modifier beside it recolors or changes the fill, as in class="button button-danger button-outline". Utilities written after the class win, so class="button px-4" overrides the padding.

button

Section titled “button”

Two kinds of modifier compose. A color sets the family: button-dark is the neutral family at the solid fill, the design system’s dark variant, and button-danger, button-warning, button-success, and button-info are the semantic solids. A fill changes how the family paints: button-outline keeps the light background with the family’s border and text, and button-ghost drops the background until hover. button alone is the default: the neutral family at the outline fill. Solid text picks black or white through contrast-color() where the browser supports it, white elsewhere.

progress-dots

Section titled “progress-dots”

A braille spinner. It freezes on its first frame under prefers-reduced-motion: reduce.

Loading

progress-dots has no states.

Give it a label

progress-dots carries role="status" and a visually hidden label as a child. Inside a busy button, hide it with aria-hidden="true" and let aria-busy carry the meaning.

progress

Section titled “progress”

A bar with a progress-fill child. It reads aria-valuenow, and when the attribute is absent the bar is indeterminate and the fill slides, except under prefers-reduced-motion: reduce. Set the determinate width on the fill.

input

Section titled “input”

The frame for a text field. Put it on a native <input>, or on a wrapper around a bare <input> to build a group with a leading icon or trailing button.

Each state also applies when the attribute sits on a direct child <input> of the frame. On a native single <select>, the class replaces the browser’s arrow with a chevron and pads the right edge for it, so the frame reads the same as a text field.

StateAttributeWhat changes
Hover:hoverA darker border.
Invalid[aria-invalid="true"]A danger border.
Warning[data-field-state="warn"]A warning border.
Read only[readonly]A transparent border and a gray background.
Disabled:disabled or [data-disabled]Disabled colors and a not-allowed cursor.

Later states win ties. Disabled and read only beat invalid and warning, and every state beats hover.

Warning state

input reads data-field-state="warn". prime-ui’s Field sets it, and plain markup can set it directly.

focus-ring and focus-ring-within

Section titled “focus-ring and focus-ring-within”

focus-ring draws a 2px outline offset by 2px on :focus-visible. button, icon-button, and input already include it. focus-ring-within draws the same ring on a frame whose focus lives on a child, and it silences the child’s own ring.

Focusable link

StateAttributeWhat changes
Keyboard focus:focus-visible (focus-ring)The outline appears.
Focus inside:has(:focus-visible) (focus-ring-within)The outline appears on the frame.

z layers

Section titled “z layers”

The config names the stacking order of floating UI, so a popover opened inside a dialog clears the dialog and a tooltip clears both. Each layer is a z-* class backed by a --z-* token. Bare numbers such as z-50 and z-1150 still work, and steps of 100 leave room for a bare value between layers.

ClassTokenValueWhat sits on it
z-sticky--z-sticky100Headers and docked bars.
z-overlay--z-overlay1000A dialog’s backdrop.
z-dialog--z-dialog1100The dialog panel.
z-popover--z-popover1200Popovers, select panels, and comboboxes.
z-menu--z-menu1200Menus. Same value as z-popover, so a consumer never has to know which.
z-toast--z-toast1300Notifications.
z-tooltip--z-tooltip1400Above everything that can carry a hovered control.
z-max--z-max9999Reserved. Nothing may cover it.
