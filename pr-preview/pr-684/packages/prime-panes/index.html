@viamrobotics/prime-panes

A layout of resizable, rearrangeable panes. layout is a tree that this package owns. A split divides its area between two children, a pane is a leaf that holds your data, a stack shows one of several panes behind tabs, and a float draws windows over a base layout. Every resize and rearrangement is assigned to layout, so bind it, or pass a getter and a setter to persist each change or veto it.

The pane snippet renders one pane, and the library never reads its content. Place Panes.DragTrigger and Panes.MoveTrigger in it so the pane can be rearranged with a pointer or without one, and Panes.TabList and Panes.PaneBody so it can stack with other panes.

The root has no default size, display, or styling. Size it with a class, or it collapses to nothing. Every other attribute of a div passes through to it.

Caution

The public API is unstable until 1.0. Expect breaking changes in minor releases.

  • The layout is a plain tree of objects that the package owns, with your data on each pane. bind:layout receives every resize and rearrangement, and a getter and setter pair can persist or veto each one.
  • Panes resize by dragging a divider or with the arrow keys, and rearrange by dragging or, without dragging, in move mode with a pointer, touch, the keyboard, or a screen reader.
  • A slot can hold a stack of panes behind tabs, or windows that float over a base layout, and a Panes view can sit inside a pane of another.
  • Pane content is yours. The library renders no header, grip, or window title bar, so you choose the markup, the icon, and the accessible name of each control.

Installation

Section titled “Installation”

  1. Install the package and its peers. The svelte peer is ^5.29.0 because the pane controls are attachments. @viamrobotics/tailwind-config comes with the package as a dependency, and installing it directly as well gives your own classes the same tokens.

    • pnpm
    • npm
    • yarn

  2. Import the package stylesheet once, after Tailwind. Tailwind skips node_modules when it scans for classes, so this file points it at the package’s compiled components and pulls in the @viamrobotics/tailwind-config tokens.

The examples on this page also use the button and input classes from @viamrobotics/tailwind-config and its color tokens, such as bg-light and text-subtle-2. The package styles only what it must, and each part that renders an element takes a class.

Anatomy

Section titled “Anatomy”

Every part is a property on Panes, and every part goes inside the pane snippet, since each one connects to the pane it renders in. All of them are optional. Panes.DragTrigger and Panes.MoveTrigger rearrange the pane, Panes.TabList and Panes.TabListDropRegion stack it, and Panes.PaneBody marks its body. Panes.TabListDropRegion goes inside Panes.TabList. Panes.MoveTrigger can sit inside a Panes.DragTrigger or stand alone.

Panes also takes an empty snippet for a layout of undefined and a dragPreview snippet for the ghost that follows the pointer.

Usage

Section titled “Usage”

Two-way binding

Section titled “Two-way binding”

Bind a $state variable to layout. Every resize and rearrangement updates it, and assigning to it from your code re-renders the view. The pane snippet renders one pane. paneLabel names each pane for the move notice, the previews, and the announcements described under Moving panes without dragging. The root has no default size, so give it one with a class, or it collapses to nothing. Every other prop of a div passes through to the root.

The layout model

Section titled “The layout model”

A layout is a tree of four node types. This section covers splits and panes, Stacks covers stacks, and Floating panes covers floats.

  • A SplitNode divides its area between first and second.
  • direction follows CSS flex-direction. In a row split, first is on the left. In a column split, first is on top.
  • ratio is the share given to first. It is strictly between 0 and 1.
  • id is unique across the whole layout: splits, panes, stacks, floats, and float entries together.
  • A PaneNode is a leaf. Its data is any value you choose. It is the generic TData, and the pane snippet receives it back.
  • A layout of undefined is an empty layout.

The pane snippet

Section titled “The pane snippet”

The pane snippet renders one pane. Its first argument is the PaneNode, so node.id and node.data are available. Its second is the pane’s PaneState, described below. The snippet’s content fills the pane, so give it size-full or an equivalent.

The optional empty snippet renders when layout is undefined.

The values of PaneState are reactive, so markup that reads them updates in place.

ValueTrue whenAttribute
isStackedThe pane shares its slot with other panes in a stack.data-stacked
isMovingThe pane, or its whole stack, is being moved in move mode.data-moving
isDragArmedA press has armed the pane to drag.data-drag-armed
isFloatingThe pane is inside a float entry, at any depth.data-floating

floatEntryId is the id of the innermost float entry that holds the pane, for removeFloat and raiseFloat. It is undefined outside a float.

Each value also appears as an attribute on the pane’s wrapper. Use the attribute to restyle, and the argument when markup or logic depends on the state. In a stack, the tabs can stand in for the pane’s title.

With the attribute alone, the same title is <h2 class="in-data-stacked:hidden">.

Function binding

Section titled “Function binding”

Panes has no change callback. State flows through bind:layout, which works in two modes: a $state variable, as above, or a getter and a setter. The setter receives each proposed layout. It is where you persist the change, and it can veto a change by not assigning the value. A vetoed change leaves the layout where it was, and a drag that is vetoed snaps back. Persisting a layout builds a save on this.

With the layout locked, the setter counts each proposal and assigns none of them, so a resize or a drop does not stick. Rearranging through move mode goes through the same setter.

Drag and move triggers

Section titled “Drag and move triggers”

Rearranging is on by default. Set reorderable={false} to turn it off. Resizing is not affected. Two parts that you place inside the pane snippet connect your markup to the pane. Panes.DragTrigger makes the elements inside it start a pointer drag, and Panes.MoveTrigger toggles move mode, the way to rearrange without dragging. Both do nothing when reorderable is false.

The two can be laid out in two ways, and the example shows both. A grip can sit inside a Panes.DragTrigger as a Panes.MoveTrigger, so dragging and the keyboard path share one element. A press on it drags at once, and a click without movement enters move mode. Or a whole header can be the drag surface, with a separate move button inside it. A press on the header drags at once, and a quick click on the button still moves.

While a pane is ready to drag, it shows a blue outline and its wrapper carries data-drag-armed. Style your own markup from it with a selector such as [data-drag-armed] header, or with Tailwind’s in-data-drag-armed: variant.

Excluding an element from dragging

Section titled “Excluding an element from dragging”

dragIgnore opts an element out of dragging. Import it from the package root. It is an attachment that needs no context. Use it on a custom widget inside a Panes.DragTrigger, such as a canvas, where a press should do something else.

Accessibility

Section titled “Accessibility”

Dragging alone fails WCAG 2.5.7 (Dragging Movements). Every pane that has a Panes.DragTrigger needs a Panes.MoveTrigger somewhere, such as a menu item. A drag that moves a stack needs one with target="stack", and a drag that moves a window needs one with target="float". Render one in each pane that can host the drag.

In development, the library warns on the first drag from a pane that has no move trigger for what the drag moves. A trigger that mounts only on demand, such as inside a menu, still warns until it first mounts.

Drop regions

Section titled “Drop regions”

While a pane is dragged, the pane under the pointer divides into regions.

RegionResult
Center (the middle 40%)The two slots swap places. A stack swaps as a whole.
Left, right, top, or bottomThe dragged pane leaves its place and splits the target, on the side that you drop.
Panes.TabListDropRegionThe dragged pane stacks with the target. See Stacks.

Every drop is assigned to layout, so a function binding sees it and can veto it.

Escape, a pointer cancel, the window losing focus, and a release outside every pane cancel the drag. layout stays as it was.

The drag preview

Section titled “The drag preview”

A ghost follows the pointer during a drag. It shows the pane’s label, or a stack’s labels joined. The library positions it in the top layer, keeps it from taking pointer events, and makes it inert and hidden from assistive technology.

The ghost shows what a drop would make. Over a tab strip or a Panes.TabListDropRegion, a drop makes a tab, and the ghost is a tab chip. Anywhere else, a drop makes a pane, and the ghost is a pane card. The ghost root carries data-form with the value tab or pane, so you can style each form.

The dragPreview snippet on Panes replaces the ghost’s content. It receives a DragPreview with a type of 'pane' or 'stack', a form of 'tab' or 'pane', the dragged panes, and the label. Keep it free of controls, since nothing inside the ghost can take focus.

While a drag that can drop onto panes is active, the root carries data-dragging, beside data-move-mode, for styling. Repositioning a floating window and a Shift drag that floats drop onto no pane, so they do not set it.

Moving panes without dragging

Section titled “Moving panes without dragging”

Dragging is not the only way to rearrange. Activate a Panes.MoveTrigger with a click, Enter, or Space to enter move mode. A button trigger reports it with aria-pressed.

Activating the trigger moves focus to the moving pane, which shows a blue focus outline, a light gray wash over its content, and “Moving Camera. Choose a destination with the pointer or arrow keys, or press Escape.” Every other pane becomes a destination that shows nothing until it is hovered or focused. A placement makes the same change a drop on that region would, and it goes through layout the same way, so a function binding can still veto it.

  • With a pointer, the region under the pointer previews with the drag indicator and the moving pane’s label. A stack onto a stacked pane previews as a tab in its strip instead. A click places.
  • On touch, a first tap previews a region and a second tap on the same region places.
  • With the keyboard, focus stays on the moving pane’s trigger. An arrow key there moves into the adjacent pane, entering at its near edge. Each destination is a labeled group with one Tab stop. Within a pane, the horizontal arrows step left, center (swap), and right, and the vertical arrows step top, center, and bottom. Past the far edge, an arrow crosses into the next pane on screen, so panes that do not touch are reachable. The moving pane is skipped, and nothing wraps at the outer edge. Enter or Space places, and Tab moves between destinations.
  • Arrows inside a text field in the moving pane stay with the field.
  • Clicking an edge bar places the moving pane on that side.
  • A screen reader in browse mode can reach and activate each side button.
  • Escape cancels move mode. So does activating the pressed trigger again.
  • Destination content is inert during move mode.
  • A keyboard-started move keeps focus on the trigger, and focus returns to it when move mode ends.
  • Moving focus out of the view cancels move mode. Focus stays where it moved.
  • A status region announces each step: the start, the placement, a cancel, and a rejected move.
  • A stacked pane’s own slot offers a reorder placement with positions. See Reordering tabs.

To restyle move mode, use data-move-mode on the root, which is present while move mode is active, and data-moving on the moving pane.

Set paneLabel so these read well. The notice, previews, and announcements use pane labels, such as “Camera placed left of Stats.”. paneLabel receives the PaneNode and returns a string. Without it the labels are pane ids.

Stacks

Section titled “Stacks”

A stack puts several panes in one slot behind tabs, such as three cameras in one camera area. In the example, switch tabs with a click or the arrow keys. Type in a field and switch away to see what unmounting loses, then turn on keeping inactive panes mounted and try again. Drag the Notes grip onto the top of the cameras’ header to stack it too.

The stack node

Section titled “The stack node”
  • A stack holds at least two panes. A stack that drops to one pane collapses to that pane.
  • A stack holds panes only. It never holds a split or another stack.
  • panes is in tab order.
  • activeId is the id of the shown pane, and it is one of panes. If it names none of them, such as after a pane is renamed in a saved layout, the stack shows its first pane, and selecting a tab repairs activeId.
  • The shown tab lives in the layout, so it persists with the rest and goes through bind:layout. A function binding can veto a tab change.

A stack renders its active pane through your pane snippet. Inactive panes unmount.

Tabs and the pane body

Section titled “Tabs and the pane body”

Panes.TabList renders the tabs of the stack that its pane belongs to, so place it in the pane snippet, usually in the header. It renders in every pane, so every pane can include it. The tablist role and the tabs appear only when the pane is stacked. An unstacked pane still carries the container, so it can be a stack target. Selecting is automatic, so focusing a tab with the arrows shows its pane, and a click selects too. Keyboard lists the keys.

Panes.PaneBody marks the part of the pane below its header. In a stacked pane with a Panes.TabList it becomes the tabpanel that the tabs control, so a screen reader announces the panel on entry. It is optional. Without it, the tabs still work and nothing claims the tabpanel role. Its rect also sets the edges and center of the pane’s drop regions, as Forming a stack describes.

Keeping inactive panes mounted

Section titled “Keeping inactive panes mounted”

Inactive panes unmount by default, so their content restarts when its tab is shown again. Set keepInactiveMounted on Panes to keep them mounted. They stay hidden and inert.

The prop applies to every stack in the view. Use it for content that is costly to rebuild, such as a live video stream.

Forming a stack

Section titled “Forming a stack”

Drop a pane onto a pane’s Panes.TabListDropRegion to stack it there. A pane without one never stacks. On an unstacked pane, the drop indicator covers the region’s rect. A stacked pane previews the drop as a tab in its strip instead and leaves the region untinted, so the tab labels stay readable while you place. The center of a pane still swaps, and the edges still split. Over a stacked target’s region, a preview tab shows where the dropped pane will land, and the drop inserts it there. See Inserting at a position.

Place the region inside Panes.TabList. Size and position it with class. Three placements work:

  • A visible strip over the tabs.
  • A grip area.
  • An edge strip that shows only during a drag.

A region shown only during a drag should also show in move mode, so move mode can stack there. The root’s data-dragging and data-move-mode attributes drive the styles. The first hit test after a drag starts misses a region that was hidden before, and the next pointer move finds it. The example’s strip sits along the very top edge of the pane, and the pane’s wrapper is the positioned ancestor.

Panes.PaneBody’s rect sets the edges and center. A point inside the pane but outside the body, such as the header, reads as the nearest edge, so a header above the body reads as the top edge. With no Panes.PaneBody, the whole pane applies. The region wins wherever it overlaps the body. Edge and center indicators still cover the whole pane, since the split acts on the whole slot.

Center always swaps whole slots. A tab dropped on another pane’s center moves its whole stack, which trades places with the target. To move one tab alone, drop it on an edge or on a region. A pane dropped on a stack’s center trades places with the whole stack.

Without a position, the dragged pane joins the end of the target’s tab order and becomes the shown pane. If the target is not stacked yet, a new stack holds the target first and the dragged pane second. Dragging a stack onto a region merges the whole stack into the target, and it shows the dragged stack’s active pane.

Forming a stack in move mode

Section titled “Forming a stack in move mode”

Move mode offers “Stack with” on each destination. See Moving panes without dragging. Press the arrow toward the region’s side to reach it. The side comes from the region’s rect against the Panes.PaneBody rect. For a strip along the top edge that is the up arrow, and a second up arrow crosses to the pane above. “Stack with” is offered wherever a region is mounted.

On a stacked target, “Stack with” takes a position, and the default is the end. The arrows along the strip pick a gap between tabs. At either end of the strip, the next arrow continues to the next region. The button name carries the position, such as “Stack Camera A with Log at position 2 of 4”. An unstacked target has one position, so its name carries none.

The wording follows the placement. On an unstacked target the preview reads “Stack Camera with Stats”, and the announcement reads “Camera stacked with Stats.”.

Placing on a stacked pane

Section titled “Placing on a stacked pane”
  • Center on a stacked pane swaps the dragged pane with the whole stack. A dragged tab moves its whole stack to the target’s center.
  • An edge places the dragged pane beside the whole stack, not beside one tab.
  • Dragging or moving a stacked pane elsewhere removes it from its stack. A stack left with one pane collapses.

Dragging a tab

Section titled “Dragging a tab”

A tab drags its own pane once the pointer moves 4px. There is no hold. A press without movement selects the tab, however long it lasts.

Reordering tabs

Section titled “Reordering tabs”

Dragging a tab over its own strip lifts it out. A preview tab marks the insertion point, and the other tabs shift to make room. The shift is animated, and it is instant under prefers-reduced-motion.

Dropping reorders the stack, and the dropped pane becomes the active pane.

For a keyboard path, press Alt + Shift + ArrowLeft or Alt + Shift + ArrowRight on a focused tab to move it one place. Focus stays on the tab, and a status message announces the move.

In move mode, the own slot of a stacked moving pane offers a reorder placement with positions. See Forming a stack in move mode.

Inserting at a position

Section titled “Inserting at a position”

Over another pane’s Panes.TabListDropRegion, the preview tab shows at the pointer’s position, and the drop inserts the pane there.

  • A region along the top or bottom of the body inserts at the pointer’s x.
  • A region along the left or right of the body appends.
  • An unstacked target appends, with no preview.
  • Insertion runs along a horizontal strip only.

Moving a whole stack

Section titled “Moving a whole stack”

The empty area of a Panes.TabList drags the whole stack. So does a Panes.DragTrigger with target="stack". A Panes.MoveTrigger with target="stack" moves the whole stack in move mode. Both take target as "pane", "stack", or "float", and the default is "pane". On a pane that is not stacked, target="stack" acts as target="pane". Inside a floating window, Panes.MoveTrigger also takes target="float", which moves the window’s pane or stack. See Windows and assistive technology.

A moving stack is named by its panes’ labels, such as “Camera A, Camera B, and Camera C”.

Drop or placement on a targetResult
An edgeThe stack lands beside the target’s slot.
CenterThe stack swaps with the target’s whole slot.
A Panes.TabListDropRegionThe stack merges into the target’s stack.

Unstacking beside its own stack

Section titled “Unstacking beside its own stack”

Dropping a stacked pane on an edge of its own stack takes it out of the stack and places it beside the rest. In move mode, the own slot of a stacked moving pane offers its four edges, which gives this a keyboard path. It also offers a reorder, one ArrowUp past the top edge, named like “Move Camera A to position 1 of 3”. The reorder starts at the pane’s current position, and a reorder announces “Camera A moved to position 3 of 3.”

Floating panes

Section titled “Floating panes”

A float node draws windows over a base layout, such as a small camera view that sits above a dashboard. In the example, drag a window’s title to move it, drag its edges or corners to resize it, and use the buttons in its body to do the same with single clicks. Pop out floats a pane from the base, and Dock starts a move of a window’s pane, so you choose where it docks.

The float node

Section titled “The float node”
  • A float node draws its windows over base, inside the float node’s own box. Nothing portals out of that box.
  • base fills the box behind the windows. It is absent once its last pane leaves.
  • Each entry in floats is one window. Its content is any layout node, so a window can hold a pane, a stack, or a split.
  • rect is in pixels, relative to the float node’s box.
  • Stacking order is array order. The last entry is on top.
  • A rect that reaches past the box renders clamped to it. The stored rect never changes.
  • An entry’s id is unique within the layout. It stays the same when a drop replaces the entry’s content.
  • A float node holds at least one entry. When its last entry leaves, the float node collapses to its base.

Float operations

Section titled “Float operations”

Five operations edit float nodes. Like the other tree operations, each is immutable, returns the same root reference when nothing changed, and returns undefined for an undefined root.

  • floatPane moves a pane out of its slot into a new window. newEntryId is the id of the new entry.
  • floatStack does the same for a whole stack, which becomes the window’s content.
  • hostId is the node whose box the window floats over. It defaults to the root. When the host is not a float node, floatPane and floatStack wrap it in a new float node with the id newFloatId. When the host is a float node, the window joins it and newFloatId goes unused.
  • setFloatRect replaces an entry’s rect. It also takes an updater, (rect) => rect, that receives the current rect.
  • raiseFloat moves an entry to the top of its float node’s stacking order.
  • removeFloat removes an entry and everything in it.

The operations never create ids. Create them at the call site.

Docking needs no operation. Dragging a floating pane onto a base pane is a movePane drop, so movePane and the other move operations take a pane out of a window like any other slot.

Moving and resizing windows

Section titled “Moving and resizing windows”

Wrap a window’s title bar in Panes.DragTrigger with target="float" to make it a handle for the window that holds the pane. On a pane outside a window it acts as target="pane", so one header works in both places, as the example’s does.

The window moves live under the pointer. No ghost and no drop regions appear, and layout receives the new rect once, on release. A function binding that vetoes the write snaps the window back.

target="pane" and target="stack" keep their meaning inside a window. They drag the pane or stack out with the ghost, so it can dock.

Shift inverts a drag. In a window, a target="float" drag with Shift held docks instead. It shows the ghost and the drop regions, and docks the window’s pane or stack. From the base, a drag with Shift held floats the pane or stack over the root at its current size, where it is released, instead of docking it.

Every window has eight resize handles, on its edges and corners. Each carries data-float-resize with its axis, one of n, e, s, w, ne, nw, se, or sw, so you can style them. A resize writes the rect once, on release.

floatMinSize is a prop of Panes. It receives the window’s FloatEntry and returns the smallest size the window can have. It defaults to 160 by 120 pixels.

Resizing stops at that size, and a window is never drawn smaller than it, unless the float node’s box is smaller.

Windows and assistive technology

Section titled “Windows and assistive technology”

Each window is a non-modal role="dialog" and can take focus. Its name is paneLabel of the panes it holds. A stack’s labels are joined, as they are in the drag ghost. With the window itself focused, the arrow keys move and resize it. Keyboard lists them. Each key press writes layout once, so a function binding can veto it. Keys typed in a control inside the window stay with that control. Keyboard moves and resizes announce nothing.

In move mode, a pane or stack in the base has a “Float” destination on its own target. It floats the pane or stack in place, 10 pixels down and right of where it was. A floating pane’s destinations include the base panes, which dock it, and the panes of other windows. A Panes.MoveTrigger with target="float" moves the window’s pane or stack.

The arrow keys in move mode stay within one layer, which is the base or one window. F6 moves to the next layer, the base first and then each window, and Shift+F6 moves back. On a Mac laptop, F6 needs the Fn key.

The status region announces “Floated Camera.” and “Docked Camera left of Map.”, with the placement, as it does for other move-mode messages.

A few more things keep a page with windows accessible:

  • Give every pane a label through paneLabel. A window’s name comes from the labels of its panes, and an unlabeled pane leaves the window unnamed.
  • A window clips at its edges. Give a focusable control that sits flush against an edge an inset focus outline, or the edge hides it.
  • Place windows so they do not cover a focusable base control entirely when the page loads.
  • The arrow keys move a window only while the window itself has focus. A screen reader in browse mode may keep those keys for itself, so the buttons in the next section matter there too.

Moving and resizing without dragging

Section titled “Moving and resizing without dragging”

WCAG 2.5.7 (Dragging Movements) asks that everything a drag does can also be done with single clicks. Arrow keys do not count, since they are not a pointer. The package draws no window chrome, so this click path is yours to render: buttons that move and resize a window, as in the example. setFloatRect takes an updater, (rect) => rect, for those buttons.

Render the same for each direction you need. Make each button at least 24 by 24 pixels. Those buttons are also what exempts the 8-pixel resize handles from WCAG 2.5.8 (Target Size).

Closing a window

Section titled “Closing a window”

A pane in a window reads state.isFloating and state.floatEntryId, so it can offer a close button that calls removeFloat, as the example does.

removePane also closes a window when it removes the window’s only pane. The pane’s wrapper carries data-floating while it is in a window, so styling can use in-data-floating: without script.

Nesting views

Section titled “Nesting views”

A Panes can render inside a pane of another Panes. A component that owns its own panes, such as a visualizer with tool panels, can then sit in an app’s layout. Each view owns its own bind:layout, and the two stay independent. In the example, the outer pane’s Panes.DragTrigger wraps the whole inner view, and dragging inside the inner view still rearranges only the inner panes.

  • A press or a drag that starts inside the inner view never drags the outer pane around it, even when that pane’s Panes.DragTrigger wraps the whole inner view.
  • Focus moving into the inner view counts as leaving the outer view. Outer move mode ends, as it does when focus leaves the page.
  • Keys pressed inside the inner view, such as Escape and the move-mode arrows, act on the inner view only.
  • Each view announces its own moves in its own status region.

The inner view does not stop events from propagating. Your own listeners on the outer view, including its onkeydown, onfocusout, and onpointerdown, still receive every event. Pane ids need to be unique only within one view. A pane cannot move from one view to the other.

Styling

Section titled “Styling”

Panes sets no size, display, or color of its own. Every part that renders an element takes class on that element:

Partclass lands on
PanesThe root div. Size it here, or it collapses to nothing.
Panes.TabListThe container div. Tabs inherit its text size.
Panes.TabListDropRegionThe inert region. Size and position it here.
Panes.PaneBodyThe body div.
Panes.MoveTriggerThe button. With a child snippet, spread props on your own element instead.

Panes.DragTrigger renders a display: contents wrapper and takes no class. Style the elements inside it.

Three snippets replace markup the library would otherwise draw: dragPreview replaces the ghost’s content, tab on Panes.TabList replaces a tab’s content, and child on Panes.MoveTrigger replaces the button. Panes.DragTrigger

Makes the elements inside it start a pane drag. Wrap a grip, or a whole header, in the pane snippet of Panes. It renders a display: contents wrapper, so it does not change layout, and it takes no class. It does nothing when reorderable is false.

What a press does depends on where it lands. A press on a plain area or a Panes.MoveTrigger drags once the pointer moves 4px, and a click on a move trigger without movement still enters move mode. A press on another control (button, a, select, or [role="button"]) drags only after a 250ms hold, so a quick click still clicks. A press on a text field (input, textarea, or [contenteditable]) never drags. A tab is the exception, since it drags at once. Once a press on a control lasts 250ms, releasing it without dragging does not click the control, a move trigger included. Keyboard activation is unaffected.

Drags run on pointer events, so mouse, pen, and touch all drag. While reorderable is true, the elements directly inside the wrapper set touch-action: none, so a swipe that starts on one drags instead of scrolling. Keep scrollable content outside it.

Panes.MoveTrigger

Toggles move mode, the way to rearrange a pane without dragging. Activate it with a click, Enter, or Space, then choose a destination with the pointer or the arrow keys. Dragging alone fails WCAG 2.5.7 (Dragging Movements), so every pane that has a Panes.DragTrigger needs one. It does nothing when reorderable is false.

By default it renders a <button type="button"> around children, takes button attributes, and sets aria-pressed. The optional child snippet renders your own element instead. It receives { props }, which you spread on that element.

Panes.TabList

Renders the tabs of the stack that its pane belongs to. Place it in the pane snippet of Panes, usually in the header. It renders in every pane, so every pane can include it. An unstacked pane still carries the container, which holds a Panes.TabListDropRegion, but the tablist role and the tabs appear only when the pane is stacked.

Give the list a name with aria-label, since a screen reader announces it on entry. Tabs inherit the list’s text size, and the shown tab carries aria-selected for styling. Each tab shows the pane’s label from paneLabel, or the content of the tab snippet. The tabs follow the WAI-ARIA tabs pattern with automatic selection. The list has the tablist role and each tab the tab role. A tab panel is opt-in through Panes.PaneBody. A tab drags its own pane, and the empty area of the list drags the whole stack.

Panes.TabListDropRegion

Marks where a dragged pane stacks onto this one. Place it inside Panes.TabList. A pane without one never stacks. It renders an aria-hidden, inert div with pointer-events-none, so only its rect matters and it never blocks the tabs under it. Size and position it with class. The pane’s wrapper is the positioned ancestor.

Three placements work: a visible strip over the tabs, a grip area, and an edge strip that shows only during a drag. A region shown only during a drag should also show in move mode, so move mode can stack there. The root’s data-dragging and data-move-mode attributes drive the styles. The first hit test after a drag starts misses a region that was hidden before, and the next pointer move finds it.

Takes className, ...rest }: Props as its props.

Tree operations

Section titled “Tree operations”

The operations behind the drops are exported, so your own controls can change the layout the same way. Each one is a pure function that takes the root and returns a new root. None of them mutates its input.

FunctionDoes
setSplitRatio(root, splitId, ratio)Sets one split’s ratio.
swapPanes(root, firstId, secondId)Exchanges two panes. Each split keeps its ratio, so sizes stay with the positions.
movePane(root, paneId, targetId, direction, key, newSplitId)Moves a pane beside another pane. A new direction split with ratio 0.5 and id newSplitId holds both.
addPaneToUpperRight(root, pane, newSplitId)Adds a pane beside the upper-right slot, in a new split with ratio 0.5 and id newSplitId. Returns pane itself when root is undefined.
removePane(root, paneId)Removes a pane. Its sibling takes its parent split’s place. Returns undefined when the pane was the only node.

removeFloat(root, entryId)Removes a window and everything in it.

Float operations covers the last five in detail.

When an operation has nothing to change, it returns the same root reference that it received. The cases are an id that names no node, a swap of a pane with itself, and a value that is already set. Compare the result to the input with === to know whether anything changed.

A subtree that an operation did not touch keeps its reference too, so $derived values and keyed blocks that depend on it do not rerun.

The other operations are stack-aware too.

  • removePane takes a stacked pane out of its stack. When it was active, the next pane becomes active, or the previous one when it was last.
  • movePane places a pane beside the target’s stack when the target is stacked. Moving a stacked pane beside one of its own stack’s panes takes it out of that stack.
  • swapPanes exchanges panes inside stacks too, and activeId stays with the position.
  • updatePaneData and addPaneToUpperRight treat a stack as one slot or find a pane inside it.

Every operation except addPaneToUpperRight returns undefined for an undefined root.

Persisting a layout

Section titled “Persisting a layout”

The setter of a function binding is the place to save. This recipe saves like the app’s teleop workspaces do.

  • A structural change (swap, move, add, or remove) saves immediately.
  • A resize saves after a short pause, because a drag produces many changes.
  • A user without write permission never saves.

To tell the two apart, compare the previous and next trees while ignoring ratio. A resize changes nothing else.

The structural save cancels a pending resize save first, because the structural tree already holds the latest ratios. The check serializes both trees without any ratio field, so pane data has to be JSON-serializable, as it is when you store the layout. A change to pane data, such as through updatePaneData, therefore counts as structural and saves at once.

The app’s format has no stack and no float. A converter must flatten each StackNode and FloatNode into its panes or reject it, because WorkspaceNode cannot hold either. The converter below rejects them.

Two differences matter when you port callers. The nodes.ts functions mutate the workspace and return it, or return undefined when nothing changed. The library functions never mutate, and they return the same root reference when nothing changed. The library also asks you for the id of any split it creates, where nodes.ts calls crypto.randomUUID() inside.

Converting between the formats

Section titled “Converting between the formats”

This converter reads a protobuf tree into the library model and writes it back. Pane data is the oneof node content, so widget code keeps working with the protobuf shapes it already knows.

Use fromWorkspaceNode(workspace.layoutRoot) to seed the bound layout. In the persistence recipe, call toWorkspaceNode inside save, and skip it when the layout is undefined. A split with a missing child collapses to the child it has, and a workspace with no layoutRoot is an empty layout. An unspecified direction on read becomes column, so the first save writes COLUMN back. That is a one-time normalization of old data.

Limitations

Section titled “Limitations”
  • A stack holds panes only. It cannot hold a split or another stack.
  • keepInactiveMounted applies to the whole view, not to one stack.
  • A swipe that starts on a drag trigger, tab, or grip drags instead of scrolling while reorderable is true.
  • Resizing needs a pointer drag on the divider or the separator’s arrow keys. It has no click-only path.
  • Escape cancels move mode only while focus is inside the view.
  • Edge buttons crowd in panes narrower than about 72px.
  • Switching browser windows during move mode cancels it.
  • While a divider is dragged, the cursor for the whole page is set by a stylesheet that the splitter injects. That stylesheet takes no nonce. Under a strict Content Security Policy it is blocked, so the global resize cursor does not change during a drag. The divider itself still resizes.
