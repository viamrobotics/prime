Component classes

The component classes are @utility classes shipped by @viamrobotics/tailwind-config. They style native elements, bits-ui triggers in prime-ui (<Dialog.Close class="icon-button">), and markup outside Svelte.

Each example below is static HTML wearing the class list it shows. Hover is not rendered statically, so the tables name the hover change in words.

A bare class is the design-system default. A modifier beside it recolors or changes the fill, as in class="button button-danger button-outline". Utilities written after the class win, so class="button px-4" overrides the padding.

button

Section titled “button”

Two kinds of modifier compose. A color sets the family: button-dark is the neutral family at the solid fill, the design system’s dark variant, and button-danger, button-warning, button-success, button-info, and button-pending are the semantic solids. A fill changes how the family paints: button-outline keeps the light background with the family’s border and text, and button-ghost drops the background until hover. button alone is the default: the neutral family at the outline fill. Solid text picks black or white through contrast-color() where the browser supports it, white elsewhere.

button-compact tightens the gap and padding and sets text-xs, for dense panels.

button-xs is the size of a toggle button item: a 24px minimum height, a 4px gap, and text-xs. Use it for a button that sits in a control row beside a toggle group. It composes with the color and fill modifiers.

button-group on a wrapper joins its direct children into one segmented control. The children are usually buttons, and any bordered child joins the same way. Neighbors share a single border and only the outer corners round. An enabled button stacks above a disabled one so the borders beside a disabled button stay visible. A hovered or focused button draws above its neighbors, so its border and focus ring are never covered. It works with every color, fill, and size modifier. Neighbors of the same solid fill show no divider, because the border is the fill color. Give the wrapper role="group" and an aria-label.

A leading icon is an inline <svg> placed as the first child.

The busy button sets aria-busy="true" and puts a progress-dots span first.

underline-tabs

Section titled “underline-tabs”

A strip of tabs that marks the selected tab with a line under its label. underline-tabs is the strip, a row of tabs 16px apart over a 1px bottom border. underline-tab is one tab in it. The selected tab draws a 2px gray-9 line over the strip’s border and sets its text semibold. Hover gives an enabled tab the default text color. Keyboard focus draws the shared outset ring, because this strip does not scroll.

file-tabs

Section titled “file-tabs”

A strip of compact, boxed tabs, like an editor’s file tabs. file-tabs is the strip, one 35px row that scrolls sideways and never wraps, and file-tab is one tab in it. The selected tab carries a line on top and drops its bottom border, so it joins the content below. Hover darkens an enabled, unselected tab, and keyboard focus draws the focus-ring-inset ring, because the strip’s scroll container clips anything drawn outside a tab. file-tab-slot is a placeholder cell in the strip, such as the spot where a dragged tab will land. It fills the row’s height and draws the same separator as a file-tab’s right edge.

status-dot

Section titled “status-dot”

An 8px state dot. Bare status-dot is the neutral gray dot. The modifiers status-dot-info, status-dot-warning, status-dot-success, status-dot-danger, and status-dot-disabled set its color, and status-dot-hollow clears the fill and keeps the ring, with or without a state. A direct progress-dots child replaces the dot with the spinner in the dot’s color on the same 8px box, so a state change never shifts layout.

The dot reads no attributes.

Label the dot

A status-dot carries role="img" and aria-label, because color alone does not name the state.

progress

Section titled “progress”

A bar with a progress-fill child. It reads aria-valuenow, and when the attribute is absent the bar is indeterminate and the fill slides, except under prefers-reduced-motion: reduce. Set the determinate width on the fill. The modifiers progress-info, progress-success, progress-warning, and progress-danger set the fill color through --progress-fill, and bare progress is info.

progress-info is the bare color, named so a tone can be set from data. progress-warning completes the set. It fills with --color-warning-text, because --color-warning-dark is under 3:1 on the gray track.

input

Section titled “input”

The frame for a text field. Put it on a native <input>, or on a wrapper around a bare <input> to build a group with a leading icon or trailing button.

input-compact tightens the padding and sets text-xs, for dense panels.

input-compact beside input tightens the padding and sets text-xs. The frame also fits a <textarea>, and a group frame takes each state from its direct child <input>. A frame with no native control takes data-disabled or data-readonly.

Disabled frame
Read only frame

readout is a read-only value box at field height. It is the input frame at the input-compact size in its readonly colors: 26px tall, a transparent border, and the gray-1 fill. A long value truncates on one line. It reads no state and does not need an <input>, so put it on a <span> or any other non-interactive element.

12.5A long value that does not fit on one line

A readout with a unit holds a readout-value and then a readout-suffix. It lays out as a row, so a long value truncates and the unit stays whole. Text put straight into a readout truncates from its end, which would cut the unit first. The suffix takes the color of a field’s suffix.

Each state also applies when the attribute sits on a direct child <input> of the frame. On a native single <select>, the class replaces the browser’s arrow with a chevron and pads the right edge for it, so the frame reads the same as a text field.

listbox

Section titled “listbox”

popover-panel is the frame of a floating panel: a light border, a white fill, and the popover shadow. Inside it, listbox-option is one choice and listbox-heading labels a group of options. An option reads data-highlighted for the keyboard or pointer cursor and data-disabled for a choice that cannot be picked. An option does not split its content, so add justify-between where a row needs a trailing part. A utility such as data-highlighted:bg-danger-light beside listbox-option wins the highlighted fill.

date field

Section titled “date field”

A segmented date entry. date-field is worn beside input on the frame, and each date-segment inside it is one part of the date. The frame rings while a segment has focus and takes a dark border while its picker is open, which beats the input hover border. The input invalid, warning, read only, and disabled borders beat the open border. An input-button inside the frame is a square icon button that darkens on hover.

A segment whose aria-valuetext is Empty shows placeholder text. A segment that is not data-segment="literal" takes a small inline padding and a medium fill on focus, so a literal separator stays plain.

calendar

Section titled “calendar”

The parts of a month grid. calendar-nav is a previous or next month button, calendar-weekday heads a weekday column, and calendar-day is one day. Today is semibold, an outside-month day is subtle, and an unavailable day is struck through. A selected day fills gray-9 under white text, which beats every other text color. On an unselected day, today’s color beats outside-month, which beats disabled.

calendar-day-range is worn with calendar-day in a range calendar and replaces its selected fill. The two ends fill gray-9 under white text. A selected or highlighted day between them takes a light fill, keeps its text color, and draws an inset 2px --color-link box-shadow. It is a shadow and not an outline, so a focused middle day still shows the focus-ring outline.

scrollbar

Section titled “scrollbar”

scrollbar-thin sets the standard scrollbar-width, and scrollbar-* sets the standard scrollbar-color to a color token for the thumb over a clear track. The rest style the WebKit scrollbar parts: scrollbar-w-* its width from the spacing scale, scrollbar-track-* and scrollbar-thumb-* their colors from the color tokens, and scrollbar-thumb-border-* the thumb’s radius, border width, or border color, by which token the value names. A browser that applies scrollbar-width ignores the WebKit parts on the same element, so use one approach per element.

A machine is a computer with components attached. Each component reports readings, and each reading can be captured and synced. A long enough paragraph overflows this box, so the scrollbar appears and shows its track and its thumb.

slider

Section titled “slider”

The slider-* classes style the track and thumb of a native <input type="range"> in both WebKit and Firefox. slider-track-* and slider-thumb-* take a color token. The -w-* and -h-* forms size each part from the spacing scale, slider-thumb-border-* sets the thumb’s border, bare slider-thumb-border makes it a round gray-bordered thumb, and the -cursor-* forms set the cursor over each part. The input still needs appearance-none, and so does its WebKit thumb.

focus-ring, focus-ring-within, and focus-ring-inset

Section titled “focus-ring, focus-ring-within, and focus-ring-inset”

focus-ring draws a 2px outline offset by 2px on :focus-visible. button, icon-button, and input already include it. focus-ring-within draws the same ring on a frame whose focus lives on a child, and it silences the child’s own ring. focus-ring-inset is the same ring at an offset of -2px, for a control flush against a clipping edge such as a scroll container. file-tab includes it.

toast-stack-item holds the stacking styles of a toast or notification item. It reads the --z-index, --x, --y, --scale, and --opacity variables that the stack’s headless machine sets on the item, and it transitions translate, scale, and opacity over 300ms. Hover transition

Section titled “Hover transition”

transition-hover-colors animates color, background-color, border-color, text-decoration-color, fill, and stroke. That is the set transition-colors animates, minus outline-color and the gradient stops, so a focus ring appears at once instead of fading in. button, icon-button, input, input-button, and calendar-nav wear it, and the --transition-property-hover-colors token mints it.

z layers

Section titled “z layers”

The config names the stacking order of floating UI, so a popover opened inside a dialog clears the dialog and a tooltip clears both. Each layer is a z-* class backed by a --z-* token. Bare numbers such as z-50 and z-1150 still work, and steps of 100 leave room for a bare value between layers.

Class Token Value What sits on it
z-sticky --z-sticky 100 Headers and docked bars.
z-overlay --z-overlay 1000 A dialog’s backdrop.
z-dialog --z-dialog 1100 The dialog panel.
z-popover --z-popover 1200 Popovers, select panels, and comboboxes.
z-menu --z-menu 1200 Menus. Same value as z-popover, so a consumer never has to know which.
z-toast --z-toast 1300 Notifications.
z-tooltip --z-tooltip 1400 Above everything that can carry a hovered control.
z-max --z-max 9999 Reserved. Nothing may cover it.
