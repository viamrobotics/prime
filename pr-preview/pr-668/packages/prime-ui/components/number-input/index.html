NumberInput

A native number input with the Viam border and padding. It renders one <input type="number">, so class lands on it and the consumer owns its width. Inside a Field it takes its id (the field’s controlId), disabled, required, state, and aria-describedby from there. Inside an Input.Group it goes borderless.

<NumberInput
  value={3}
  min={0}
  max={10}
  step={1}
  state="none"
/>
  • Its own native <input type="number">. It takes the same state as Input and works inside an Input.Group with a Field.StateIcon.
  • value is number | undefined. No string parsing on your side.
  • min, max, and step are the native attributes. The browser owns stepping, spin buttons, and the wheel.

Styling

Section titled “Styling”

Same as Input: class lands on the <input>, and it carries no width. Inside an Input.Group the input goes borderless and the group carries the border. The input carries data-field-state and aria-invalid from state.

Keyboard

Section titled “Keyboard”

Native number input behavior: ArrowUp and ArrowDown step by step within min and max. Nothing is added or intercepted.

API

Section titled “API”
PropTypeDefaultDescription
bind:valuenumberCurrent value. An empty field is undefined.
minnumberThe minimum allowed value.
maxnumberThe maximum allowed value.
stepnumber | 'any'1Step for keyboard or spin-button increments, and the granularity constraint validation enforces. 'any' accepts every decimal, which no number can express.
stateFieldStateContextual state. Defaults to the enclosing field's state.
