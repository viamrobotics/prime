@viamrobotics/prime-tree

@viamrobotics/prime-tree renders a tree of your own nodes and is headless. The package owns behavior and accessibility, including keyboard navigation, roving focus, selection, and expansion. You own the markup of every row through the node snippet, so the tree draws no chrome.

Caution

The public API is unstable until 1.0. Expect breaking changes in minor releases.

Installation

Section titled “Installation”

  1. Install the package and its peers. The svelte peer is ^5.29.0. @viamrobotics/tailwind-config comes with the package as a dependency, and installing it directly as well gives your own classes the same tokens.

    • pnpm
    • npm
    • yarn

  2. Import the package stylesheet once, after Tailwind. Tailwind skips node_modules when it scans for classes, so this file points it at the package’s compiled components and pulls in the @viamrobotics/tailwind-config tokens.

Quick start

Section titled “Quick start”

The snippet contract

Section titled “The snippet contract”

nodes holds the root nodes and is the single source of truth. A later change to it flows into the tree without a remount. The accessors tell the tree how to read your node type: nodeToValue returns a unique id, nodeToString returns the label used for type-ahead, and nodeToChildren returns the children. nodeToChildrenCount and isNodeDisabled are optional. Return a number from nodeToChildrenCount for a branch that may be empty, such as an empty folder, so it still renders as a branch, and undefined for a leaf. Any number, including 0, makes the node a branch.

branchClick decides what a click, Enter, or Space on a branch row does: 'toggle-and-select' (the default) opens or closes the branch and selects it, 'select' only selects it and leaves opening to the trigger, and 'toggle' only opens or closes it, for a tree whose branches are folders rather than choices. The trigger always toggles.

The node snippet receives the node and its TreeNodeState. It runs once per visible node. Return a Tree.Branch for a branch or a Tree.Item for a leaf. Inside a branch, Tree.BranchControl holds the row you see, and Tree.BranchContent renders the children.

The package sets a --depth custom property on Tree.Branch and Tree.Item, and a branch’s control inherits it. Use it in a style attribute for indentation, as the quick start does. state.depth is the script-side equivalent.

The package renders only what the snippet returns, so the tree adds no wrappers or default styles. A collapsed branch never calls the snippet for its children.

To arrange the rows yourself, pass a children snippet to Tree or to Tree.BranchContent. It receives the nodes at that level, and you render one Tree.Row per node you want shown, with the node’s index among those nodes. That is how a branch with hundreds of children goes through a virtual list, or how an empty branch shows a placeholder:

The nodes a children snippet receives are typed unknown, since a part cannot see the root’s node type. Narrow them once with a helper or a cast.

Each part spreads the attributes you pass over its own, so class, style, and event handlers all work. Each renders children, except that Tree.BranchContent treats children as the row renderer described above and Tree.Row renders no element of its own. Tree.Item leaves aria-current to you.

State

Section titled “State”

The second argument of the node snippet is a TreeNodeState.

FieldTypeMeaning
valuestringThe node’s value from nodeToValue, the key expanded and selected hold
isBranchbooleanThe node has children, or nodeToChildrenCount says it may
expandedbooleanThe branch is open and its children render. Always false on a leaf
selectedbooleanThe node is in selected
focusedbooleanThe node holds the roving focus, whether or not the tree has DOM focus
disabledbooleanisNodeDisabled returned true. A disabled node cannot be selected or expanded
depthnumberNesting depth, starting at 1 for a root node. Matches aria-level and --depth
indexPathreadonly number[]The index of the node and of each ancestor within its siblings, root first

Indentation is yours. Use depth as in the quick start, or read the --depth custom property that each row carries.

Selection and expansion

Section titled “Selection and expansion”

bind:expanded and bind:selected hold arrays of node values. Both take the plain bind: form. selectionMode is 'single' by default and 'multiple' allows several selected rows. expandOnClick defaults to true, so a click on a branch row toggles it.

Both also take a function binding. The setter runs on each change and can refuse it by not assigning. This example keeps a locked folder from closing.

Accessibility

Section titled “Accessibility”

The root renders one element, role="tree", with tabindex="-1". Rest props land on it, so name the tree with aria-label or aria-labelledby, size it with a class, and make it the scroll container with overflow-auto when the tree is taller than its box. To reach the element itself, pass an attachment through the rest props.

Focus is roving. One row has tabindex="0" and the rest are reachable by the arrow keys, so the tree is a single tab stop. Rows carry aria-expanded, aria-selected, aria-level, aria-setsize, and aria-posinset. A branch row shows expansion with a visual icon, and Tree.Indicator is aria-hidden, so the label inside the row must name the node.
