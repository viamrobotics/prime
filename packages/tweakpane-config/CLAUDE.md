# @viamrobotics/tweakpane-config

Viam-themed configuration for [`svelte-tweakpane-ui`](https://kitschpatrol.com/svelte-tweakpane-ui). Exposes preset `Theme` objects matching the Viam design system. Consumers apply them with `svelte-tweakpane-ui`'s own `ThemeUtils` API.

## Surface

- `primeTheme`: the light `Theme` object. Pass it to `ThemeUtils.setGlobalDefaultTheme(...)` or to any component's `theme` prop. See the [`svelte-tweakpane-ui` themes docs](https://kitschpatrol.com/svelte-tweakpane-ui/docs/themes) for the usage patterns.
- `primeThemeDark`: the dark variant of `primeTheme`, with the same shape. Its values mirror the dark tokens in `@viamrobotics/tailwind-config/dark`. Tweakpane themes are applied via JS, not CSS, so nothing activates it from `prefers-color-scheme` or `.dark`. The consumer decides which theme to pass, for example from a `matchMedia('(prefers-color-scheme: dark)')` listener.

The `Theme` type is not re-exported. Import it from `svelte-tweakpane-ui`.

## Layout

- `src/lib/` is the published source. `src/lib/index.ts` re-exports the public API.
- `src/lib/theme.ts` holds both theme objects as plain hex and rgba values.
- `src/lib/__tests__/` holds the parity spec that checks `theme.ts` against the tailwind-config stylesheets. It is excluded from `dist/`.
- `test/svelte-tweakpane-ui.ts` stands in for `svelte-tweakpane-ui` under Vitest, aliased in `vitest.config.ts`, because the package exports its entry only under the `svelte` condition.
- The demos live on the package's page in [docs](../../docs/), under `src/content/docs/packages/tweakpane-config/`. This package has no Svelte tooling of its own.
- `dist/` is generated by `tsc -p tsconfig.build.json` during `pnpm build`. It is what npm sees via the `files` field.

## Peer dependencies

- `svelte ^5`
- `svelte-tweakpane-ui ^1.5.16`

## Conventions

- Theme hex values mirror tokens in [`@viamrobotics/tailwind-config`](../tailwind-config/CLAUDE.md). The values are inlined rather than referenced via `var(--color-*)` because `svelte-tweakpane-ui` doesn't reliably resolve CSS var references inside its theme values. If you change a token in `tailwind-config.css`, update [src/lib/theme.ts](./src/lib/theme.ts) to match. The parity spec parses both stylesheets and fails when a `theme.ts` value differs from its token, or when a key is neither mapped to a token nor exempt. Add new keys to its table.
- Light values come from the Viam design system at https://design.viam.com/ through the tailwind-config tokens. The design system publishes no dark palette, so dark values come from the `--dark-*` tokens. Don't invent values.
- This package is data-only: it exports two theme objects. The decision of _where_ and _when_ to call `ThemeUtils.setGlobalDefaultTheme` belongs to the consumer (SSR concerns, lazy initialization, etc.). Resist the urge to add a helper that wraps it.
- The docs islands pass `theme={paneTheme}` per component, derived from the site theme that `docs/src/components/theme.svelte.ts` exposes. They do not call `ThemeUtils.setGlobalDefaultTheme`: it applies to the document root, and svelte-tweakpane-ui 1.5.16 removes a root variable it finds already set to the same value, so several islands calling it with one theme toggle it off.
- Fonts are not bundled. Consumers load them separately via `@viamrobotics/tailwind-config/fonts` or `@fontsource-variable/public-sans`.

## Commands

```bash
pnpm --filter @viamrobotics/prime-docs dev            # docs site; the demos resolve this package to its source
pnpm --filter @viamrobotics/tweakpane-config build    # tsc -p tsconfig.build.json + publint
pnpm --filter @viamrobotics/tweakpane-config test     # vitest parity spec
pnpm --filter @viamrobotics/tweakpane-config check    # tsc --noEmit
pnpm --filter @viamrobotics/tweakpane-config format   # prettier formatter
pnpm --filter @viamrobotics/tweakpane-config lint     # eslint
```
