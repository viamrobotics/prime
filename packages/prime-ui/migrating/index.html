Migrating from prime-core

@viamrobotics/prime-core shipped Svelte 4 components, actions, and helpers. @viamrobotics/prime-ui is Svelte 5 only, and some helpers did not carry over because the platform now covers them or because they were never UI. The table below maps each one to what you use now.

What to use instead

Section titled “What to use instead”
OldNowNotes
uniqueId$props.id()Per instance and safe under SSR. No shim ships.
createHandleKeyuseHotkeyShortcuts register where the behavior lives and list from one registry.
clickOutside actionThe clickOutside attachmentUse {@attach clickOutside(handler)}. Portaled content the element links counts as inside.
persistedStays in your appIt is a storage helper and not UI.
useToastprovideToast and useToast, see ToastprovideToast goes once near the root, and the Toast region renders the stack.
useNotifyprovideNotify and useNotify, see NotifySame provider and consumer split as the toast.
BannerBannerSame name.
ProgressProgressSame name.

Icons

Section titled “Icons”

@viamrobotics/prime-core’s Icon took a curated kebab-case name such as icon="cog". Icon in prime-ui takes an import, so replace each name with the one below.

The tables cover a name written in markup. An icon that arrives as data, such as name={option.icon} or a field typed IconName, needs a map on your side from your own keys to the imports you use, since Icon in prime-ui carries none. Keep that map to the names your app renders.
