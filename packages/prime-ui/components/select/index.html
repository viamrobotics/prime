Select

A select. Render Select.Trigger, Select.Portal, Select.Content, Select.Viewport, and Select.Items inside it. Inside a Field it takes disabled and required from there.

Built on bits-ui Select.
  • Composed from parts, so the trigger, the panel, and each item are yours to arrange.
  • One value, bindable. items is the single source of truth for the options: it gives the closed trigger its label, drives typeahead while the list is closed, and Select.Items renders it.
  • Keyboard navigation, typeahead, and the WAI-ARIA listbox pattern, via bits-ui.
  • Select.Trigger takes state from an enclosing Field, or directly. error sets aria-invalid="true" and a red border. warn sets a warning border. Both come from the same input component class as Input.
  • The panel floats in a portal, positioned to the trigger, and scrolls when the list is long.
  • One value at a time. For several, MultiSelect takes the same parts with a string[] value.

Anatomy

Section titled “Anatomy”

Every part is a property on Select. Portal and Content are required for the panel to float. Viewport is the scrolling region, and Content should contain one. Items renders every entry of items as a Select.Item, and renders no element of its own. Group and GroupHeading are optional.

To arrange items by hand, for example under group headings, compose Select.Item instead. items is still required on Select for the closed label.

Usage

Section titled “Usage”

Two-way binding

Section titled “Two-way binding”

bind:value on the root. Pass the options as items and render them with <Select.Items />.

Fully controlled

Section titled “Fully controlled”

Pass bind:value a getter and a setter. State & binding explains both modes.

Rendering the options

Section titled “Rendering the options”

Three ways turn items into rows. All three keep items on the root, which the closed trigger and typeahead read. The difference is who writes the loop.

ApproachUse it when
<Select.Items />Every option is its label plus a check when selected. The default, shown in the two-way example above.
Select.Items with a children snippetEvery option shares one custom layout. The snippet receives { item, selected, highlighted }, with item the entry from items.
{#each} over Select.ItemThe rows need something items cannot carry: extra data per row, groups, scroll buttons, or rows that are not one-to-one with items.

One snippet for every option

Section titled “One snippet for every option”

Pass children to Select.Items. The snippet sees item as a SelectOption, so value, label, and disabled. A row that needs more data per entry is the by-hand loop below. The trigger’s chevron is an indicator snippet on Select.Trigger in the same way.

Items by hand

Section titled “Items by hand”

Loop over your own data and render a Select.Item per entry. Select.Item takes the same children snippet without item, since the loop already has the entry in scope. items stays on the root so the closed trigger can show the selected label.

Groups and scroll buttons

Section titled “Groups and scroll buttons”

The by-hand form is also how you add structure. Wrap related items in Select.Group with a Select.GroupHeading. For a list taller than the panel, put Select.ScrollUpButton and Select.ScrollDownButton around the viewport. They appear only when there is more to scroll in that direction.

Placement

Section titled “Placement”

Select.Content takes side and align to place the panel, and sideOffset and alignOffset to nudge it. The API table lists each option and its default. The panel flips to the other side when there is no room.

Migrating from a native select

Section titled “Migrating from a native select”

A prime-core Select was a native <select> with <option> children and an onchange. The same control here is items plus the six parts, and the value comes through bind:value instead of the event.

Select.Trigger has no width of its own, so the class that sat on the old wrapper goes there. A state that sat on the old <select> goes on the trigger too, or on an enclosing Field.

Styling

Section titled “Styling”

Every part that renders an element takes class on that element. Select.Trigger carries no width of its own, so set one with a class such as w-64 or w-full. Focus shows as the same 2px ring every prime control uses. Select and Select.Items render no element, so they take no class, and Select takes no event handlers. onfocus, onblur, onkeydown, and the rest go on Select.Trigger, the real <button>. The panel width follows the trigger through --bits-select-anchor-width. Its max height follows --bits-select-content-available-height. bits-ui sets both variables. bits-ui also sets the data attributes in the table below. Select.Content wears z-popover; see z layers.

Keyboard

Section titled “Keyboard”

With focus on the trigger:

KeyAction
Enter / Space / ArrowDown / ArrowUpOpens the panel.
Printable charactersSelects the next item from items matching the text, without opening.

With the panel open:

KeyAction
ArrowDown / ArrowUpHighlights the next or previous item.
Home / EndHighlights the first or last item.
PageDown / PageUpHighlights the item a page away.
Enter / SpaceSelects the highlighted item and closes.
Alt + ArrowUpSelects the highlighted item and closes.
Printable charactersTypeahead: highlights the next item matching the text.
EscapeCloses without changing the value.
TabCloses and moves focus on.

PropTypeDefaultDescription

Select.Trigger

The button that opens a Select. Inside a Field it takes its id (the field’s controlId), state, and aria-describedby from there. An error state sets aria-invalid and the error border, and warn the warning border, the same input class from @viamrobotics/tailwind-config an Input wears. Pair it with a Hint or a Field.StateIcon that says what is wrong, since the border color alone is not a signal everyone can see.

Add a Select.Value child to show the current selection.

A trailing chevron is rendered by default. Pass an indicator snippet to replace it:

PropTypeDefaultDescription
indicatorSnippetReplaces the trailing chevron.
stateFieldStateContextual state. Defaults to the enclosing field's state.

Plus everything in HTMLButtonAttributes, spread onto the element.

Select.Value

Renders the selected option’s label inside a Select.Trigger, falling back to placeholder.

Takes extraClasses, ...restProps }: Props as its props.

Select.Viewport

The scrollable region inside a Select.Content that holds the items.

Takes extraClasses, children, ...restProps }: Props as its props.
