Notify

The notification stack: a live region that shows each notification made through useNotify as a Banner with a countdown bar. Render one near the app root, below a provideNotify. It positions itself, so it needs no wrapper. The item snippet replaces the Banner with your own layout.
  • Render one Notify region per app, below a provideNotify.
  • useNotify has info, success, warning, danger, and pending. Each returns { id, dismiss }.
  • The default item is a Banner with a countdown bar.
  • pending has no timer and shows a spinner in the chip.
  • persist: true keeps a notification until the user dismisses it.
  • update turns a pending notification into its result.

Toast or notification?

Section titled “Toast or notification?”

A notification reports something that happened to the user, such as a failure, a lost connection, or long-running work. It carries a title and may persist. A toast confirms an action the user just took, such as Saved or Copied, and goes away on its own.

Anatomy

Section titled “Anatomy”

Notify is the region, and it renders one item per notification. The item is a Banner, and the item snippet replaces it.

Usage

Section titled “Usage”

Basic

Section titled “Basic”

provideNotify and Notify live in one component, and any component below it calls useNotify. The second argument is an optional description.

Pending

Section titled “Pending”

pending shows a spinner and never dismisses itself. Pass the id it returned to update to turn it into a result, which starts the countdown.

Persistent

Section titled “Persistent”

persist: true keeps the notification until it is dismissed. onDismiss runs once it has gone, however it went.

With details

Section titled “With details”

The description is a string or a snippet. A snippet renders whatever markup you give it, such as monospace error output.

Custom item

Section titled “Custom item”

The item snippet receives the notification’s state and composes the Banner parts itself. The notification keeps its live-region role and its stacking motion.

API

Section titled “API”

Takes extraClasses, item }: Props as its props.

useNotify

Section titled “useNotify”

useNotify returns the methods below, and provideNotify returns the same object. The variant methods take (title, description?, options?), where description is a string or a snippet and options takes duration, persist, and onDismiss.

MethodDescription
info(...)Shows an info notification and returns { id, dismiss }.
success(...)Shows a success notification.
warning(...)Shows a warning notification.
danger(...)Shows a danger notification.
pending(...)Shows a spinner and no timer. Resolve it with dismiss or update.
update(id, changes)Changes a visible notification in place. changes takes variant, title, and description.
dismiss(id?)Dismisses one notification, or every notification without an id.

provideNotify takes placement (default top-end), duration (default 8000 milliseconds), and max (default 5).
