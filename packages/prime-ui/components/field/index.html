Field

Groups a label, a control, and hints, and wires their ids and ARIA for you.

The parts read the control id, disabled, required, and state from the field. Label points for at the control. Each Hint joins the control’s aria-describedby. RadioGroup takes aria-labelledby from the labels. Field.StateIcon shows the state. A prop passed to a part directly still wins.

An error state sets aria-invalid on the control and changes its color. Color is never the only signal, so pair it with a Hint that says what is wrong, or with Field.StateIcon.

Lowercase letters, numbers, and dashes.

<Field
  required={false}
  disabled={false}
  state="none"
/>
  • Generates the control’s id (controlId) and hands it to the label’s for and the control.
  • Collects every Hint into the control’s aria-describedby, and names a RadioGroup from the label.
  • disabled, required, and state set once here reach every part.
  • A prop passed to a part directly always wins over the field’s value.

Anatomy

Section titled “Anatomy”

A field is a plain <div> around one control, with any number of labels and hints in any order. Its one part is Field.StateIcon, which shows the field’s state as an icon.

What the parts take from the field

Section titled “What the parts take from the field”
PartReads from Field
Labelfor (the control id), required, disabled
Hintdisabled, state (error turns red, warn and info are colored too), and joins the control’s aria-describedby
Input, NumberInputcontrolId, disabled, required, state, aria-describedby
CheckboxcontrolId, disabled, required, state, aria-describedby
RadioGroupcontrolId, disabled, required, state, aria-labelledby, aria-describedby
Select / Select.Triggerdisabled and required on the root, and controlId, state, and aria-describedby on the trigger
Field.StateIconstate, and renders nothing for none

A Hint in an error field is described by the control, not announced. To have a screen reader read an error the moment it appears, pass role="alert" to that Hint. It goes straight to the <p>.

Styling

Section titled “Styling”

Field renders a bare <div> and takes no layout stance, so pass class to stack or inline its parts. controlId is the id the field assigns to the control. Pass your own to point an external <label for> or a test selector at it. A plain id lands on the wrapper <div>.

API

Section titled “API”
PropTypeDefaultDescription
controlIdstringId the field assigns to the control inside. Generated when omitted. id lands on this wrapper.
disabledbooleanfalseDisable the control and dim the label and hints.
requiredbooleanfalseMark the control required and show the asterisk on the label.
stateFieldState'none'Contextual state shared with the control and hints.
childrenSnippet<[FieldContext]>The parts. Receives the field context, with controlId, disabled, required, and state.

Plus everything in Omit<HTMLAttributes<HTMLDivElement>, 'children'>, spread onto the element.

Field.StateIcon

Shows the icon for a Field’s state, or for its own state prop outside a field. Renders nothing for none. Place it after the input inside an Input.Group, or anywhere in the field.

Takes extraClasses, ...restProps }: Props as its props.
